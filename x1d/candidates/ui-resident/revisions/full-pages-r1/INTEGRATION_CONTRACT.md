# 后续合包接口与验收约束

本文件只记录 UI 候选的集成要求，不表示其他模块已经独立通过，也不新增合包或持久安装授权。按当前安排，四模块先分别测试，再由主任务确认集成。

## 资源与装载

- UI 的 6 个覆盖资源及有效摘要见 `build/resources/manifest.json`。其他模块若涉及同一路径，必须在一个共同基线上合成最终内容并重新绑定、编译和回归；不能依赖注册先后决定赢家。
- 本库拦截 `qRegisterResourceData` 和 `QQmlApplicationEngine::load(QUrl)`，原函数均通过 `RTLD_NEXT` 取得。多个 preload 同时使用这些 hooks 时，调用链、每个原厂调用的次数、RCC 注册时机和撤回顺序都须在最终组合中重新验证。
- 当前地址与 GUI 摘要严格绑定 X1D 1.25.0；不能把它外推至其他 GUI/固件。

## 生命周期与成功条件

- 常驻对象必须跟随原厂 GUI 引擎及原页面父对象生存，GUI 退出即结束。本版没有独立守护进程。
- 完整成功必须保留本版“3 菜单、23 页、每页实际行 Ready”的门槛，再叠加其他模块自己的真实就绪条件。资源注册、函数命中或库已出现在 maps 中均不足以表示组合可用。
- 额外 AF 调试 UI 的去留由 AF 模块独立确定。不能据此删除本模块的正常菜单界面。
- UI 隐藏时的原生 Connections、确认拥有者、Slider 绑定以及临时格式化对话框必须继续通过原有离线检查；组合版还需重新测量实际相机内存和冷启动预热。

## 安装、恢复与持久化

- 当前脚本只在 `/run/systemd/system` 添加本包拥有的临时 GUI drop-in，发现其他 drop-in 或 preload 就拒绝。组合工程需要新的共同拥有权与恢复设计，不能删掉当前保护来强行叠加。
- 独立包只重启 `victory-gui`，不重启总线或改变其他服务；失败时核验拥有权并恢复原厂。恢复不得覆盖其他任务的文件或接管未知状态。
- 持久自启尚未实现。要有新的持久化工件、逐模块关闭开关、失败回退、幂等安装/撤回、重启后 PID/资源/对象池核验及相机实测，才能标记完成。

## 当前待验证项

目标 Qt5.5 实際启动和 warning、LCD/EVF 显示、实际页面池预热时间、可用内存余量、全部普通页面的实机交互、设置与对话框正确性、独立撤回，以及最终四模块组合和重启后的行为均待主任务安排。离线替身通过不能替代这些结果。
