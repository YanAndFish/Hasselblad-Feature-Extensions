# 第一代 X1D 外露 USB / SD 恢复入口矩阵

2026-09-10；独立、有界调查。静态主输入为官方 **X1D-50c 1.25.0**，不是实机版本确认。实机版本、板号、启动熔丝及当前控制器状态未知。详细地址、输入哈希、脚本和限制见 [证据说明](EVIDENCE.md)。

**当前没有核实出用户能通过机身外露 USB 或两张 SD 卡、在错误 1000 下直接恢复或首次烧录整机的操作。** 这不是认定相机无法修复：本轮把正常 SD 更新、i.MX 下载、FX3 下载及 FARM 启动分开，并取得了此前缺失的固定原包证据。

| 候选入口 | 芯片能力与固定版本证据 | 板上/外口可达性 | 运行依赖与当前用户可操作性 |
|---|---|---|---|
| **SD 卡上的官方 CIM** | 1.25.0 GUI 选中 CIM 的 UUID，再由升级器解包；正常卡访问经 `FarmStorage → FarmProxy`。这是原厂用户更新链。[E1、E4] | 外露卡能用于正常更新有原厂依据。不是 i.MX ROM 直接读取 CIM；是否在当前故障下仍可完整读卡未知。 | 需要 Linux、界面、Storage/FARM、升级准备状态和其他控制器可用。用户已报告菜单约 5–6 秒后被错误页覆盖、日志写卡失败；**未证实当前可以完成，不安排抢时间更新或重复 Retry。** |
| **外露 SD → i.MX ROM / 包内 U-Boot 启动** | i.MX6 一般有 SD/MMC 启动能力；但 Wedge DTB 的 USDHC1/2/3 均 `disabled`，仅 USDHC4 为 8 位 `non-removable`。包内 U-Boot 的 MMC 配置只指向该 USDHC4，Linux 根分区使用 `mmcblk3pN`。[E1、E2] | 固定软件配置指向内置 eMMC；未找到外露两卡槽直接接到 i.MX ROM 启动总线或能从外部切换过去的证据。DTB 不能单独证明所有物理连线都不存在。 | 包内默认流程从 eMMC 加载 Linux，没有外露 SD 救援分支。**不能给用户“制一张 i.MX 启动卡”的步骤。** 缺卡槽/复用器接线、启动选择条件和匹配加载器。 |
| **外露 SD → FARM / Xilinx 启动** | 已把 Wedge 的 even/odd 两份 FARM 镜像按位平面重组，通过启动头、3 项分区头校验。其 FSBL 读取启动模式低 3 位，只分派 `1=QSPI`、`2=NOR`、`0=JTAG`；`5=SD` 进入 `ILLEGAL_BOOT_MODE`。Fallback hook 最后为自分支。[E3] | FARM 应用有 SD0/SD1 存储、SD 时钟和扇区读写代码；不能由此推出外露槽接到了 Zynq ROM 可用的 SD 引脚。 | **本版原包 FSBL 不能直接充当 SD 启动恢复加载器。** Zynq 芯片的通用 SD 启动能力不能补上此缺口。需要 Wedge 板级启动条件及不同于这份原包 FSBL 的合适恢复载荷。 |
| **电脑 USB → 当前 FX3 应用接口** | 1.25.0 Wedge FX3 镜像按 `CY` 分段格式校验通过；USB 2.10 和 USB 3.00 描述符均为 `2756:0002`，有对应初始化调用。[E5] | 与此前被动 PnP 快照 `2756:0002` 相符，支持正常 FX3 接口解释；不能仅凭编号确认当前版本、设备型号或控制器健康。也没有证实改用 USB 2 线会改走 i.MX。 | 正常通信至少依赖 FX3 应用和目标处理链。**没有核实出该应用接口在错误 1000 下可执行的整机恢复命令、写入端和回退条件。** 枚举成功不等于电脑已获得刷写入口。 |
| **电脑 USB → FX3 自身 Boot ROM** | Infineon 说明 FX3 USB 启动由 PMODE 条件决定；默认 ROM 下载设备为 `04b4:00f3`，也允许定制启动方式。Wedge 原厂脚本通过机内 I²C 写 FX3 EEPROM，并控制其电源/总线 GPIO。[E5] | FX3 芯片能力明确；未取得 X1D PMODE 接线、合法外部进入方式或当前 ROM 枚举证据。现有 `2756:0002` 与原包应用描述符匹配，不能当作 ROM 模式。 | **即使进入 FX3 ROM，也首先是给 FX3 加载程序，尚不等于能重写 i.MX 的 NOR/eMMC 或 FARM/SUC。** 缺板型匹配的第二阶段程序、目标桥接协议及恢复条件；当前不提供操作。 |
| **电脑 USB → i.MX6 Serial Downloader / UUU** | NXP 有 ROM 下载与制造工具能力；Wedge Linux 的 OTG 节点启用，`ci_hdrc.ko` 同时含 host/gadget 实现。[E1、E6] | 芯片、驱动存在不等于 Type-C 的 D+/D− 接到了 i.MX OTG。未确认插座到 SoC/FX3 的线路、mux 上电状态、启动脚条件及量产允许状态。当前也没有归属于相机的 USB 网络接口。 | **没有形成当前用户可操作的 UUU 链。** 包内 U-Boot 无 `fastboot/dfu/ums/sdp` 命令项，不能直接套用通用制造脚本；专用 RAM loader 和完整写入配置未取得。 |
| **U-Boot 从 USB 存储读取 `loader.hbl` / `hblupdate.img`** | 1.25.0 包内 `usbboot` / `usbupdate` 使用 `fatload usb`，后者执行载入脚本；默认 `bootcmd` 不调用两者，`preboot` 为空、`bootdelay=0`。[E2] | 这是引导器当 USB 主机读存储设备，不是电脑推送。未证明该 host 通路接到机身插座，也未找到机身按键入口或所需两份载荷。 | 需要先到达 U-Boot 控制台或已设置入口、可用 USB host 线路和匹配载荷。`bmode` 有命令表项，但有效模式表注册仍未闭环。**当前无用户步骤。** |

`E1–E6` 对应 [证据说明](EVIDENCE.md) 的同号条目，均绑定到具体输入；矩阵没有把上游开发板条件写成 X1D 的事实。

此外，Wedge DTB 把 `u-boot/env/env-redundant` 放在 **SPI NOR**，U-Boot 再从 **eMMC** 加载 Linux。FARM 使用另一对 QSPI 存储，FX3 又有自己的 EEPROM。因此“把 Linux 卡写好”或“只回退 Linux 分区”不能自动覆盖全部控制器的恢复。[E1、E3、E5]

下一步需要的资料已缩小到以下三类；不是扩大权限即可补齐的问题：

1. **第一代 X1D / Wedge 对应板号的接线页**：Type-C 的 USB 2/3 数据线、FX3/i.MX 之间是否有 mux 及其上电状态、FX3 PMODE、i.MX/Zynq 启动选择，以及两外露 SD 槽连接到哪一控制器/引脚。仅有芯片手册不够。
2. **匹配的制造/维修恢复包及说明**：RAM loader、识别板型和存储布局的配置、供电/复位条件、各目标写入顺序、保留校准区的规则，以及失败后的恢复办法。现有 CIM 包及 `loader.hbl`/`hblupdate.img` 字符串没有组成这套资料。
3. **明确支持此故障状态的合法服务协议**：能说明外露 USB 的哪个接收程序负责日志诊断或恢复、依赖哪些控制器、错误 1000 时是否仍能工作。仅有 Phocus/SSH 名称或端口配置不能替代它。

本轮未读取相机、照片或机内日志，未建立 USB/网络/串口会话，未生成或执行可刷镜像；完整 FARM 重组结果仅存在内存中。只在本独立目录写了报告、清单与验证脚本；原研究文档及增强候选未修改。本阶段调查完成，已将结果交回来源任务协调。
