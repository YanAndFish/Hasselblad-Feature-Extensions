# 当前 AF 设置候选交付

本文件供主任务串行装载使用。本任务始终为 0 设备请求。候选支持原厂默认速度、五/四/五手动档、远端优先、默认关闭的抗噪判向，以及两项提前量独立保存回读。**快扫提前减速和精扫提前停止的实际动作尚未接通**，不能将页面显示和保存成功当作完成这些动作。

参数最终语义和页面见 `PARAMETER_CONTRACT.md`。保持原厂速度时也可以单独人工覆盖补偿；初始/恢复原厂会撤销覆盖。0 ms 是人为设定的绝对零提前量，不是原厂值。速度为原厂模式且尚无真实命令回读时，按钮明确显示“手动”并进入最低手动档。

## 离线状态

`build/delivery-validation.json` 当前通过：12 项 ARM 协议/原厂局部路径测试，8 项首次/升级/回滚事务模型，以及桌面 QML 交互和渲染。来源文件、冻结旧观察版输入、两份重定位候选、两个 Qt 库和报告均逐文件绑定。

- `settings_loader.py report` 只检查文件，输出 `offlineReady`，不建立设备连接。
- `first-install` 直接要求原厂 AF 入口和零 bootstrap，申请新 32 KiB 并安装。**不得先安装旧观察版。** 正式 HFS1 必须由主任务先独立安装，随后 AF 事务只读核对其代码、入口及空闲状态。
- `upgrade` 仅用于旧观察版仍存活的同一次开机；匹配旧日志 nonce、代码、入口、分配头和 READY 状态。换电重启后的身份不匹配会零写入拒绝。
- `rollback --journal <本轮完整设置安装日志>` 是独立的新事务。历史升级回滚至旧观察版；首次安装回滚至原厂 AF。两份堆块均保留，不释放代码或重新 malloc。它不接受部分安装或不完整事件链。

三个有设备动作的入口仅由主任务运行。本任务未运行它们，也没有取得设备窗口。恢复日志在本目录 `recovery/`，每次新建独占文件与追加事件链；不会复用、覆盖或自动恢复旧日志。

## 现场先决条件与失败边界

1. 主任务先独占当前开机的新组合窗口，检查器固定为 `/tmp/hbl-x1d-combined/system-check`；最低剩余 180000 ms，主机每段预算 120000 ms。固定检查器 SHA-256 为 `e373262db5b23f567b22060f1a61687c723cbbbae3c1e237e60728015d3ccca0`。
2. 主任务先验证目标 Qt、组合资源及服务，正式 HFS1 已驻留且空闲。装载期间 AF 设置页不发配置查询。AF 加载器不会安装 Linux 服务、RCC 或创建/续期/释放窗口。
3. 先只读检查固定版本、回调、AF 状态及 HFS1，再建立持久化日志。经缓存执行回执后申请 32 KiB；整个新块与旧块/HFS1 不重叠，剩余堆至少 128 KiB。
4. 完整上传、缓存可见与自有 Thumb 执行回执后，逐一替换 14 个入口。全部验证通过才释放 AF gate，并恢复原厂临时回调。两项时序动作能力仍为 0。
5. 任一传输、缓存 ACK、句柄关闭、窗口或日志失败立即停止；不重试、不自动回退、不释放堆、不重启相机。部分失败必须根据 `phase`、`inFlight`、`cacheInFlight` 作专门恢复审查，不能调用完整安装回滚去猜状态。

当前模型首次安装为 23273 请求 / 5075 写入 / 66 次 hold；历史升级为 26559 / 5075 / 73。它们是模型计数，不是实机时间承诺。主机固定上限 32000 请求，hold 上限 96 次；模型覆盖了写前/写后不确定失败、旧身份缺失、原厂基线不符、重叠/不足分配、完整回滚及回滚中断。

目标 Qt 5.5.1 真实 IPC、现场执行和实际效果仍必须由主任务在本轮独占流程中验收。原始 18 张样本、36 张派生输入和 48 组局部策略检查已重新验证，它们不构成毫秒时序标定。
