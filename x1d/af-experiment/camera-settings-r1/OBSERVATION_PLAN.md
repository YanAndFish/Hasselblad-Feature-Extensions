# 当前观察版的最小取证与解释边界

用户观察：初始判向异常、扫到端点后折返，经过画面肉眼最清晰处仍继续运动，有时再次折返。尚未读到这次动作的标量记录，不能据此认定 ROI 停止更新、原厂峰值算法失效或观察钩子导致故障。

## 已装记录器可以区分的路径

先由主任务确认用户 AF 已结束、相机空闲，再安排既有只读快照。AF 任务本轮保持零设备请求。

| 环／记录 | 最小字段 | 能回答的问题 |
|---|---|---|
| IRQ `NC_RAW` | sequence、generation、state、observed tick、原始 a/b、组合 mode、视频模式位 | 各已记录阶段原始反差来源是否继续产生值，组合模式有无变化 |
| AF `NC_CV_FIFO` | CV、入队 slot、head、队长 | 原始反差是否进入原厂 AF FIFO |
| AF `NC_POSITION_FIFO` | signed position、slot、镜头序号（模 100）、head | 镜头位置是否继续报告，方向是否转变 |
| AF `NC_ACCEPTED` | accepted count、位置、CV、两 FIFO head | 配对后被接受的样本是否增长、清零或停止，已接受反差曲线是否出现峰后下降 |
| AF/控制 `NC_COMMAND` | 阶段、原厂请求参数、实际交给原厂封包的参数、调用开始 tick | 记录范围内是否从试探转入快扫/精扫，命令符号和幅值是否改变 |
| 控制 `NC_CYCLE` | generation、raw/AF sequence | 窗口是否跨 AF 周期；周期开始与尾部记录是否仍在环中 |

固定容量为 IRQ 64、AF 128、控制 32，每条 36 字节，另有 48 字节头。完整上限 224 条；读取必须同时验证已装代码、12 个钩子、分配身份及前后头一致。不能只抓一条 CV 或只比较最大值。三环分别属于 IRQ、AF_SERVICE、AF_SERVICE_SM，相同 tick 不能决定跨任务先后。

## 当前缺失、不能由现有环补造的字段

- 每次判向函数是否执行、它返回的指标与阈值拒绝原因。
- 原厂速度过滤每次拒绝的原因和当次估计速度。能看到 FIFO 前进但 accepted 停滞，只能定位到候选环节，不能确定是哪一条件。
- 端点事件及搜索反转的直接原因。位置变化/符号反转可观察，原因需要事件记录。
- 原厂 peak 检测结果、拟合目标、结果有效性、最终定位 `0xCF` 包、所有 `0xCD=0` 停止调用。现有命令钩子只覆盖选定阶段调用点。
- 物理曝光帧号、ROI 坐标／尺寸更新与所见画面的对应关系。a/b 是既有 FPGA 反差通道，不能等同用户注视区域的肉眼清晰度。
- 命令送达镜头及机械停止的实际时刻；入口 tick 不是这些时刻。不能把两个日志 tick 相减标成电机停机延迟。

若起始数据被覆盖，需要标为“环已截断”。不能把尾部的第一条当作整轮 AF 的第一条。FIFO 数值匹配可作关联线索，重复 CV、缺失记录和模序号回绕都可能造成歧义。

## 观察钩子的审计方向

当前 observation r1 新判向与速度覆盖关闭，但这不足以证明记录器零影响。应逐个核对覆盖指令回放一次、条件标志恢复、ARM/Thumb 与浮点调用约定、原厂函数调用次数、环的单写者与发布顺序，以及 IRQ/两个任务的附加指令开销。计数器记录、周期重置和封包包装都有执行成本。未获得无钩子与有钩子的可比实测之前，不排除调度／时延影响。

最小增量候选宜记录：判向调用与结果；速度过滤拒绝；峰值事件/目标；最终定位与停止封包。各项应绑定固定固件调用点，保持原厂调用和每环单写者，并先用 ARM 离线执行验证。没有经过这些步骤，不应为了补日志直接增加实机钩子。
