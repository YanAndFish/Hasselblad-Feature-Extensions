## 执行顺序

1. 阅读[等待状态](recovery/r5-deferred-install-state.json)及已有`full-r5-*.json`恢复锚点。已安装则核对记录并停止等待；已启动、有失败、未知结果或不完整记录则先审查，不能再次执行安装。
2. 核对当前工作区、明确的最新释放消息及用户是否暂停/改指令。先运行下面的本地report，必须仍返回同一artifact、合同与`experimentalInstallReady=true`。同步核对上述验证记录哈希。
3. 在电脑等待状态中记录释放依据和`installing`状态，再启动一次下列install命令；保存命令进程ID及后续返回值。安装命令自己先执行版本、所有原代码/保留RAM、AF空闲等冷预检，然后才创建追加恢复记录并写入。任何基线不符为零写入停止，需要说明具体前提，不重复轮询USB。
4. 正常完成后用`InstallJournal.read_record`离线核对本次锚点和完整事件链：`installed_armed_until_restart`、`installed/armed`、`allHandlesClosed`，以及`inFlight/cacheInFlight`为空、无不完整尾部。把实际计数、恢复记录路径和结果写回等待状态及安装报告。异常保持全部记录和驻留代码，不自动重试、自动恢复或自动清理回调。
5. 成功、失败或需要用户手动操作时通知用户；安装成功后停止此等待任务。未变化时不重复发状态。安装完成只代表临时RAM装载与启用，不代表实际合焦或160行时序已验证；用户试用另按当前对话安排，不由此等待程序自动触发。

