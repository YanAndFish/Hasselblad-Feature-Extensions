## 控制流程

1. 用户启动普通单次 AF 后，原厂负责启用采样；本算法开始独立周期。按已知镜头分段信息选择初次 `±20000` 试探，尚无图像证据时不把该方向称为已知正确方向。
2. 每一段先跳过一个新接受样本，至少取得五个位置不同的有效样本。比较最近变化、局部噪声和持续下降；如果已有内侧峰值，直接建立峰值两侧范围，否则错误方向最多折返一次。若试探 120 tick 后已有五个有效点但仍无法确认方向，也允许一次有界反向搜索。每次改变运动命令后停止处理该批旧方向样本。
3. 粗扫需要两侧清晰度低于峰值，差值至少为峰值的 5% 或六倍估计噪声。粗扫中的真实曲率不能一直累计成噪声；进入精扫后保留本段最大噪声估计，减少偶发平滑噪声被认成峰值。
4. 停止粗扫，使用自己的位置目标回到峰值前方。精扫半宽按已观察的位置范围计算，限制为 64–960 个镜头位置单位；它不是毫米或屈光度。随后以 `±3000` 精扫。精扫的两侧差值至少为峰值的 1% 或六倍估计噪声。
5. 在峰值附近用实际位置和三个清晰度值作有界整数拟合；保留已知镜头加性校准，发送自己计算的位置目标。位置回包与新位置反馈均到达后检查误差；仅允许一次本算法自己的位置误差修正。
6. 停位后再等待稳定，并要求三个新的清晰度反馈通过检查，才发送正常 AF 成功结果。缺少证据时停止并报告失败，不回到原厂 AF 搜索、找边缘、拟合或自适应位置重试。

清晰度仍来自原厂接受数组，位置与清晰度的 FIFO 配对及速度筛选属于保留的输入前端；原厂原先维护的峰值变量不会参与本算法决策。算法不自动选择框内主体。中央小／中／大 ROI 的尺寸仍是 124×28、174×40、248×56 个 AF 统计像素，详见 [ROI 核对](ROI_ANALYSIS.md)。

## 限制与失败处理

- 原厂 AF 状态 3 中的搜索由本算法接管，原厂状态 4–6 的搜索／拟合分支不可作为回落路径；意外进入则失败停止。取消、手动覆盖和原厂错误出口继续使用正常终止流程。
- 每轮总运动预算 2400 RTOS tick，试探 250、单段扫描 700、位置移动 600、末端确认 250。首次启动无数据限制 500 tick；位置反馈超过 100 tick 未更新即停止。已有 tick 读回只支持近似毫秒量级，不能当物理精密计时。
- 相对起点移动不超过 8192 个位置单位，位置限在 `[-32760,32760]`；每段自有缓存最多 64 点，原厂计数不能超过 500 或倒退。未知镜头状态、行程终点、计数／数值异常、ROI／帧率／镜头档位变化均有明确退出。
- **不等帧间隔尚非完全不敏感。** 最终拟合使用实际位置；五点趋势和噪声仍受位置间隔变化影响。原厂 FIFO 没有共同时间戳配对的证据，未实测 CV 与位置时差。本版不混合短帧，也不声称已解决光照闪烁或逐帧自动曝光变化。
- 20000 是机身协议单位，不是马达 RPM。来源任务的 75P 参考参数中，`20000 × 4 × 0.20768 ≈ 16614`，可能被该参考路径的 16000 软件上限钳制；不改该限速。实际镜头版本和实际速度待测。FARM 档位 18 的速度容差参数 `0x2adc3c` 为 float32 `0.9700000286`；对应容差乘积 19400 仍在 s16 内，不因这一乘法发生符号翻转。

## 安装与显式恢复

[full_loader.py](full_loader.py) 默认 `report` 只查看电脑文件。`install` 才访问设备；先要求精确构建验证文件未过期，然后检查固定版本、原厂十处入口和旧三处入口、代码、12000 速度、档位、AF 空闲、中断守卫，以及整个候选区域为零。任何预检不符都不写入。

写入前保存独立 `full-owned-*.json`，每次写入前保存 `inFlight`。随后运行并恢复最小 RAM 探针、上传候选、同步指令缓存、挂接十处入口、将三处速度改为 20000、恢复中断回调及暂存区；完整读回通过后最后写 `armed=2`。整个安装不发送 AF、拍摄、闪光、重启或永久写入命令。USB 每次交换均关闭句柄，异常不自动重试或自动撤回。

```powershell
python -B .\x1d\af-experiment\full_loader.py report
```

设备操作仅在当时已接回、唤醒且没有其他任务使用设备的窗口执行；写入期间用户不半按、不按 AF-D：

```powershell
python -B .\x1d\af-experiment\full_loader.py install
python -B .\x1d\af-experiment\full_loader.py status --record full-owned-<实际时间>.json
```

两个恢复动作都必须明确执行，不会自动运行。先核对记录与当前 RAM 仅含本次已知状态；未知代码或重启后的 5000 不盲目覆盖。

- `restore-algorithm --record <文件名>`：恢复原厂十处入口，最后保留用户指定的 20000。
- `rollback --record <文件名>`：恢复原厂入口和本次安装前记录的 12000。

恢复后保留不再引用的代码区域用于诊断，不在可能还有返回地址时擦除。存在本版恢复记录后构建器拒绝覆盖对应二进制；后续改版必须另建版本输出。断电恢复不依赖电脑，也不会由电脑自动重装。
