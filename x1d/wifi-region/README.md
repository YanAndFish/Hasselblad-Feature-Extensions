# X1D 无线地区：原厂维护接口修改记录

本次用户明确要求把第一台的仅 2.4 GHz 地区改为第二台的欧洲地区。只修改无线地区，不复制其他机身的生产资料。

## 已验证

- 第一台原值 `WifiRegion2gOnly=2`，第二台为 `WifiRegionEU=0`。编号 2 不等于名为日本的地区枚举。
- 固定 X1D 1.25.0 的 configstore 普通 ProdInfo 属性只读；独立 sutest-daemon 的 ProdConfig 有可写属性 `WifiRegion`，索引 13，命令 49，get 功能 2，set 功能 1。没有调用初始化功能。
- 实机 sutest-daemon SHA-256 与离线分析文件一致：`382f6d2c41dd2dbe0425eff0e2906206cbc5f466d26c686f39e09832ebc23f2f`。
- 原厂 setter 在 `0x224dc`，调用 `0x214bc` 读改写：地区位于出厂资料偏移 `0x30`，校验位于 `0xfc`。它自己更新校验并重新读取，不需要另行直写 EEPROM。
- 原始 8192 字节 EEPROM 在相机数据分区保留权限受限的备份，没有导出到主机日志。原生维护 getter 写前读到 2；只发送一次 set 后，新一次 getter 读到 0。
- 比较完整 EEPROM，只有地区字段和校验的各一个字节改变，其他生产和校准数据一致。
- 用户正常重启后反馈 Wi-Fi 页面已出现 5G。实际热点连接质量尚未验证。

## 文件状态

`native_region.py` 为固定字段维护请求和严格响应校验工具，默认运行离线测试，`--read` 只查询地区。写事务结果见 `native-installation.json`。对外分发前仍需单独审查授权和内容。

`region_change.c` 是找到原厂入口前准备的底层方案，仅做过主机模型测试及编译；未上传、未执行，未用于此次写入，不应作为后续默认操作路径。

X2D 的原厂配置文件及地区编号不同，不能直接复用本型号的偏移或枚举。
