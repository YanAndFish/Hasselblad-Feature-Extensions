## 回放和持久化
- [ ] 自动回放和手动回放均使用自建控件页面；仅在原厂页面中替换图像来源不算完成。两种入口共用 JPEG-only 策略，缓存加载、引用释放的时机仍按原厂策略核对，不能因重做页面另起一套未经验证的缓存生命周期。
- [ ] 回放用配对 JPEG，沿用原厂缓存生命周期，处理 JPEG 尚未写完及不存在。
  - 用户最新明确：所有回放只使用 JPEG；没有对应 JPEG 时显示黑色，禁止回退到 3FR/RAW，也不能继续显示上一张照片冒充当前照片。JPEG 未完成时不得转读 RAW。
  - 覆盖拍摄后的自动回放与手动回放；自动回放遇到 JPEG 尚未生成或未写完时也显示黑色，后续加载及释放沿用原厂策略。两条入口分别验证，不能用手动回放通过代替自动回放验收。
  - 自动回放必须锁定本次拍摄身份，不得用目录最后一张/最近一张代替；本次照片尚未加入目录或 JPEG 未完整写入时等待，写入就绪后重试同一张，不以黑屏作为自动回放完成。
  - JPEG 就绪后显示不额外等待 RAW 全部落盘。用户明确：写卡顺序只分析、不实施；不得修改编码顺序、生产队列或 RAW/JPEG 写卡调度，不能把显示端就绪条件说成已经调整写卡顺序。
- [ ] RAW＋JPEG 实际格式与禁用的菜单一致，不只是改显示文本。
  - 画质固定 RAW＋JPEG，不提供 RAW-only；需验证实际配置值、进入页面及设置恢复后的行为，不能仅删掉菜单选项。
- [ ] 完整离线验证通过后才组合装 RAM；回读、错误日志及用户交互验收分开记录。
- [ ] 最后持久化另做冷启动验证；临时 RAM 成功不等于持久化交付。
