# 后续装载架构约定

用户明确要求：最精简引导器先装入接收端，后续操作由接收端组织。适用于当前项目后续装载设计；语音中的机型名称未重新确认，不据此把X1D 1.25.0地址直接用于其他机型。

- 引导器只保留首次接收、最低限度缓存同步和交接；不能将大量业务逻辑放进逐字上传的引导器。
- 接收端分块上传，负责本地校验、缓存同步、入口切换、原厂任务交接、初始化和收尾。等待用异步状态组织，禁止在消息或中断回调里阻塞等待其自身依赖。
- 固件兼容性按安装时绑定策略处理；运行中只保留当次必要状态确认。
- 以整次冷启动的通信与时间验收，包括自举、新增代码上传及最终退出；不得将组件通过表述成整机通过。
- 新命令必须验证主机构造、发送白名单、原厂框架、接收端解码/执行/返回全链路。当前故障表明独立ARM接收端与C++替身不覆盖主机真实白名单。

当前已安装候选在native-allocation失败，缓存命令被主机旧白名单拒绝；另有960字节实际范围与976常量不一致。尚未修复上机，不重复执行已有部分写入。

用户补充：开发与测试都以一组命令组成一个逻辑任务，接收端依序本地执行、遇错停止、最终返回。物理数据分包不等于恢复逐命令往返；仍须清楚报告尚未完成任务化的阶段。
