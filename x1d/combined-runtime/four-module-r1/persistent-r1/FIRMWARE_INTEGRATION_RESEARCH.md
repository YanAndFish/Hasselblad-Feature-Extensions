# 固件集成可行性核查

对象：第一代X1D，官方1.25.0。此次只读本地源码及已有审计资料，无相机请求、无刷写、未生成修改镜像。输入摘要保存在build/firmware-integration-research.json。

## 结论

有明确研究落点，尚未达到可刷写状态。把新增代码随FARM应用启动初始化，有机会去掉当前开机后跨处理器逐字预检、上传、校验和发布钩子的流程。该收益为架构推断，不是性能实测，也不能保证一秒。运行程序仍使用RAM；目标是取消事后修改原厂运行内存的安装流程。

## 已核对依据

- 原厂program_nodes.sh对Wedge选择FARM even/odd镜像，由program_farm.sh编程。FARM应用属于独立控制器载荷，仅替换Linux源文件不能证明控制器已改动。
- 现有固定镜像解析器检查两份输入摘要、解交织整幅摘要、第三分区头加和，再取FARM应用。应用大小1808280字节，加载及入口为0x100000。分区头校验不等于已覆盖整个控制器启动认证链。
- 既有升级器审计记录AES封装和MD5内容校验，已审计路径未见公钥验签。此为有界静态证据，不能宣称整机没有认证或修改包一定被接受。
- 原厂整包程序还会更新SPC、FX3、触控及SUC。Linux双分区试启动不构成上述控制器的整体回退保证；SUC存在失败后擦除分支。
- 当前装载器先全面原厂预检，再调用原厂分配器获取自有堆，按堆地址重定位AF正文，发布并验证钩子。故不能把本次实机堆地址或当前RAM快照直接固化。

## 按组件处理

|组件|集成方向|尚缺证据|
|---|---|---|
|界面、设置、回放|Linux用户态组件及启动配置|启动依赖与整包更新副作用隔离|
|自动对焦|FARM启动期分配、重定位与初始化|初始化入口、堆就绪顺序、镜头/任务并发条件|
|闪光时序|FARM正文和调用逻辑集成，保留原厂动态修正|静态空间归属、状态初值、缓存和执行顺序|
|无线相关修改|对应无线固件载荷与驱动初始化配套|与FARM/Linux的版本及握手一致性|

## 下一阶段验证边界

先对原始镜像进行无修改拆分/重组的逐字节往返验证；再核对FARM分区布局、数据校验及原厂初始化调用链。形成独立离线候选后，验证默认关闭行为、原厂动态闪光修正、初始化失败处理和地址归属。修改镜像被接收与控制器可恢复必须分别验证，不能用现有Linux安装回退测试代替。没有可验证恢复路径前，不把候选报告为可刷包。

本报告没有证实固件集成是唯一提速路径，但它能针对现有跨处理器加载瓶颈，值得继续研究。
