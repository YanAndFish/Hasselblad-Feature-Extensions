# 全流程合并任务离线核对

当前完整实现仍为883次，不是本报告提出的单任务已实现。逐次采集完整模型：数据包36次（接收器9、分配程序4、正文和初始化请求23），单独读写/控制847次。

|逻辑段|当前次数|可合并方向|
|---|---:|---|
|最初运行确认|42|可后移的动态确认由早期代码本地执行；首次覆盖前依赖仍须核对|
|首次缓存环境|110|引导自举依赖，现有接收器尚不可执行，不能直接用后续批量通道替代|
|微型引导及接收器建立|368|含9个接收器包、52个初始字写入及读回；剩余发布/缓存控制可研究微型引导器本地完成|
|接收器建立后的状态及缓存阶段|32|并入开始任务的本地确认|
|分配程序上传、入口准备|120|含4数据包；其余可作为任务启动动作，在正确上下文触发分配|
|分配等待及结果读取|22|原厂对焦任务异步完成，任务进入等待态；不能阻塞消息或SGI回调|
|恢复临时分配入口、启用上传窗口|69|分配完成后的本地续段|
|上传正文及初始化器准备|87|23数据包保留，窗口和缓存控制可本地执行|
|初始化、收尾、最终结果|33|主体已在控制器内，仍须处理最终结果和中断退出|
|总计|883|不是能直接全部删除的次数|

可以组织为一个逻辑任务，但必须有自举、接收数据、异步分配等待、初始化收尾等内部状态。任务不是一包，也不是一次阻塞函数调用。当前框架尚未实现任务调度/恢复入口，不能给出新通信总数。

进行了28项抽象事件顺序试验，覆盖每个事件缺失、重复、阶段失败及相邻乱序，拒绝在数据不全或分配未完成时推进。该试验只验证状态图，不执行原厂调度，不证明真实ARM任务交接；已有883次完整模型及其故障测试不等同于新状态机验证。没有相机请求、没有安装。
