# 一秒装载目标：初步边界核算

用户希望把额外模块装载缩到1秒。此处以模块开始到modules-ready计时，不混同整机上电到进入系统。

最新实机199593ms/19086请求，平均约10.46ms每次。当前读请求8字节+回包9字节，写请求12字节+回包5字节，且串行等待。原厂msg2dbus服务配置921600波特；仅计算8个数据位、忽略串口起停位和所有帧封装，约324kB有效报文也需要2.8秒以上。因此保留当前请求集合和逐条协议无法达到1秒，减少线程等待仍不足。

可研究的结构变化：把原厂校验、重定位、复制和最终校验放到FARM本地执行，只传代码/数据块和结果摘要。还必须解决冷启动时这段机内初始化程序本身如何快速进入FARM；不能拿它已经驻留内存的时间冒充完整冷启动装载时间。现有EIM驱动没有已验证的通用FARM内存映射，不能把任意地址当作Linux指针直接memcpy。

边界：现有稳定版本已完成真实冷启动；一秒路径未实现、未实测。暂不修改原厂启动固件、刷写或尝试未知硬件通路。先离线核对原厂批量传输/启动路径及缓存一致性，再判断能否在保留原厂固件前提下实现。无线准备阶段也应计入额外装载整体目标，不能只优化AF后宣称所有模块一秒。

## 原厂批量通路的离线核对

以下仅针对官方 X1D 1.25.0 FARM 应用，SHA-256 `317841f6f4dff599cda8c83f2b4912f78534db20e7690d0b14b0cd5f1b8c39ca`。缓存输入 `build/fast-start-research/farm-1.25.0.bin` 来自此前已验证的官方 bootimage 第三分区，不是当前内存回读。

- EIM 编排 `0x1fa890` 要求长度为512字节倍数，先获取资源10；目标最高位决定 DDR2/DDR3 分支。DDR3 地址转换 `0x1f5dc4` 仅清除最高位，不能据此推断任意 CPU 地址都可达。
- 完成函数 `0x1fabe0` 等待对应通道；失败调用对应终止函数，随后清除活动标记并释放资源。它没有传输校验和验证，成功状态不能替代补丁数据的完整校验。
- `CodeTests/eim_original_check.py` 在 Unicorn 中执行原厂编排机器码，DMA、资源、日志调用使用替身。9个用例通过：两个地址分支各自成功、准备失败、等待失败，以及资源忙、无传输时完成、长度未对齐。报告 `build/fast-start-research/eim-original-validation.json`。替身地址仅验证分支，不是获准写入的实机地址。
- 原厂 movie 数据入口 `0x1b62b0` 后续在 `0x1b6a18` 调用该编排。分支可使用 `burstmem.c` 的 `0x2165f4` 分配结果；该分配器直接读写块头并返回块头后8字节的指针。另一分支使用独立 `ddr3burst.c` 分配器 `0x21c5d4`。这支持“至少有 CPU 可寻址缓冲区参与”的静态推断，仍不足以证明我们的堆块和可执行区可由相同 DMA 安全访问。
- DDR2 通道1描述符在 `0x2b1900`，目标与长度寄存器分别为 `0x41000000`、`0x41000008`；`0x212e8c` 经原厂寄存器访问函数设置它们。没有对相机执行这些访问。

实际缺口是机内入口、DMA/CPU地址映射、缓存一致性和完成后完整校验。EIM 原厂调用会获取资源并等待，不能直接放进当前 SGI 中断回调，避免阻塞其依赖的调度或中断。正常拍摄/movie入口也不能直接复用为安装请求。

当前 `boot_transport.cpp` 使用回复唤醒条件变量，没有固定每请求10毫秒的 sleep；10.46毫秒仅为总装载时间除以请求数的平均值，不能归因于该文件中的固定延时。原厂内存基线7545个字分布在39段连续区间，适合机内按块校验；应保留全部覆盖范围、动态掩码检查及失败停止语义。
