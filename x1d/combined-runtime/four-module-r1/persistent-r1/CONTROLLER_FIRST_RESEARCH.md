# 控制器内部检查与初始化候选

目标是缩短独立对焦持久自启动的完整耗时，保持对焦逻辑和参数。当前实机基线主装载133.395秒，系统开机到解除保护约140.751秒。此处候选没有安装。

早期只读接收器已由2504缩到2216字节，无AF堆依赖。真实ARM模拟覆盖批量比较、拒绝上传、普通请求透传、控制帧透传、CRC错误及越界，执行原厂外层长度过滤、真实转义帧解码、CRC16与发送函数。15个用例通过，包含20项满批、转义字节、双层CRC错误、地址拒绝、错误会话/序号/掩码、比较不匹配和发送失败。RTOS队列、普通读回调及错误日志仍为ABI替身，不能据此宣称完整硬件链路验收。代码位于native/boot_early_read_adapter.c，可由build_controller_first.py重建；模拟证据read-only-arm-validation.json。

拟议暂存地址仅来自已用闪光载荷区域的离线候选。在独立AF配置不启用闪光补丁时可研究复用，但体积适合不代表归属/全生命周期已验证。还必须在首次写入前确认固定区原厂状态、缓存与消息入口；发布后按本轮已写适配器验证该区域，不能继续要求其全部为零，也不能将其从验证中无条件跳过。退场时必须恢复原厂入口并核实临时区域处理。

现有适配器入口校验只覆盖若干函数开头，不构成完整依赖验证。新的entry-dependencies.json发现读处理、发送及缓存操作继续调用其他函数，记录仅为前128字节扫描，不宣称完整控制流或间接调用闭环。不能据已有局部模拟直接部署早期入口。

初始化迁入控制器尚未完成。原厂堆分配需满足任务上下文，不能从消息解码器直接调用原AF分配流程。应在正常任务上下文进行初始化，明确跨核缓存同步、失败标记与禁止功能提前启用的边界。比较操作可按批流式发送，避免为完整精确比较基线额外上传约26KB数据。成本必须包括引导器装入、入口发布、全部检查、初始化及撤销，不能只报告驻留后的检查时间。

常规独立AF模型回归仍通过19273项检查，13042次模型请求，没有闪光写入，消息入口恢复。缩小只读接收器只启用编译期比较分支；常规适配器保留原读写路径。此轮尚未接入启动与更新事务，没有相机写入，也没有新的冷启动实测。
