# 无线三状态候选（离线验证通过，实机切换待验证）

## 用户确定的行为

原 Wi-Fi 设置页的两态开关与引闪页按钮均点击循环“关 → Wi-Fi → 引闪 → 关”，共享状态，分别显示关闭、Wi-Fi、闪电图标。拍摄参数页不新增三态按钮。

Wi-Fi 使用原厂保存的 2.4G/5G 选择；引闪固定 2.4G。不得为引闪覆盖原厂保存的频段。切回 Wi-Fi 要恢复原厂驱动、网络管理和热点功能。关闭应关闭两种无线用途，不能仅把发送开关设为 false 后继续占用芯片。

## 已核对

连接相机上 network-manager、hostapd 均为 inactive，radio-prepare.status 为 ready/0，wl band 为 b。既有 prepare-radio 脚本开机就停止这两项服务并装入测试无线固件。因此不按快门也会失去原厂热点。另一台尚未单独读回，不能把本机状态直接当成两台的测量。

当前完整基线由质量 85 的 full-jpeg-output 清单开始，后续另有质量 95 单组件更新。三状态不得覆盖 JPEG、拖动和启动修复。

## 本轮实际完成

- 新建 native/radio_mode_policy.h：先停引闪、确认 master/held/busy 均释放，再交接驱动；匹配事务回执后发布状态；重复点击、拍摄中操作、旧回执、超时均受控。
- CodeTests/radio_mode_policy_test.cpp 已在主机编译运行，覆盖所有模式转换、旧回执、保持占用、失败和超时。
- 已接入固定版本 Runtime 与 worker：关闭确认的忙状态包含射频实际持有，收到关闭回执后才运行驱动交接。
- 首次安装将共享 RadioModeButton 放在拍摄参数页和引闪页，入口位置不符合用户要求。后续 build/radio-wifi-page 纠正为原 Wi-Fi 设置行及引闪页，并恢复原拍摄参数页。原物理 Wi-Fi 键仍进入同一选择入口。
- 开机协调器取消强制 prepare-radio，旧 Master 参数不再自动开启引闪。冷启动读取原厂 Wi-Fi 当前状态；若原厂 Wi-Fi 已开，保留它，否则显示关。引闪需要用户选择。
- 原厂频段和地区字段不修改；用户切换时只通过原厂 WIFI_power 开关配合恢复原厂驱动/服务。状态文件和引闪固件副本仅放在 /run。
- QML 实际点击测试、状态机测试、真实脚本配合设备替身的交接测试、五种安装/回退场景均已通过。它们不等于机内切换测速或热点可发现性实测。
- build/radio-three-state/installation.json 记录实际安装结果；build/validation.json 中的 hardwareSwitchVerified 仍为 false。
- Wi-Fi 页纠正版的资源差异、点击交互和安装回退模型均已验证；实际安装状态以 build/radio-wifi-page/installation.json 为准，不能把打包成功当成已上机。

## 实机验收

1. 用户正常重启后确认整包完整启动，两处按钮状态一致。
2. 选择 Wi-Fi，确认手机能搜到原厂热点；驱动/热点服务就绪检查不能替代这一步。
3. 切引闪，确认热点停止及引闪实际可用；再切 Wi-Fi 确认恢复。
4. 检查原厂频段选择保持，质量 95 的全尺寸 JPEG 输出保持。
5. 若显示未就绪或切换失败，保留连接读取记录，不把旧模式显示当成成功。驱动交接中断后本版要求重启重建状态，不猜测驱动当前身份。
