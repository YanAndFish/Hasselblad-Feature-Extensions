# EF-HX V1.04：Canon EF 50mm F1.8 STM 对焦速度字段

## 结论

针对 `EF-HX_PUB_V104.bin` 中的 Canon EF 50mm F1.8 STM 配置：

- 转接环在线路回复中写入的两个速度字段均为十进制 **71**，即 `0x0047`。
- X1D 1.25.0 原厂动态镜头参数解析路径会把该字段乘以 100，因此机身缓存的“镜头上报启动速度”为 **7100**。
- `71` 是线路原始字段，`7100` 是 X1D 内部对焦命令尺度。二者都不是镜头组移动的毫米/秒、转速或完成一次对焦所需时间。

## 固件身份

- 文件：`EF-HX_PUB_V104.bin`
- 文件大小：32,820 字节
- SHA-256：`F6F5C8DC416CEBE2A40A3E975862B57E43B2069F4F270F0113EB25C2A93A13FE`
- 16 字节头：`PRODUCTVER:1.001`
- MCU 映像基址：`0x10000`

本文所有 EF-HX 地址都指去掉 16 字节文件头后的 MCU 映像地址。分析只读取固件文件，没有访问相机或转接环。

## 镜头配置表

`0x12e3c` 从 `0x17b26` 开始扫描 52 条记录，每条 18 字节（9 个 little-endian `uint16`）。匹配条件包含镜头 ID、最短焦距、最长焦距和变体字段。匹配成功后，`0x1585a-0x1586a` 取相应记录并把记录 `+6` 传给参数装载函数 `0x12c28`。

Canon EF 50mm F1.8 STM 位于零基索引 49、地址 `0x17e98`：

```text
[4156, 50, 50, 34, 4232, 710, 0, 0, 0]
```

其中 `4156 (0x103c)` 是 Canon EF 50mm F1.8 STM 的 LensType。焦距字段为 50/50。第 4 个字段 `34` 与近摄距离类字段的使用方式吻合；本结论不依赖对该字段的命名。

## 转接环的换算

`0x12c28` 把记录中的 `4232` 和 `710` 装入运行时参数。`0x1329c` 根据 `710` 计算尺度：

```text
710 <= 2550
scale = 200
```

当机身请求动态镜头参数时，`0x12196-0x121b2`（另一路等价代码位于 `0x104f8-0x10514`）计算：

```text
reported = (((710 + 5) / 10) * 2 * 100) / 200
         = 71
```

这里均为整数运算。随后固件把 `71` 以 16 位值写入回复的两个速度字段，所以两项均为 `0x0047`。

同一配置中的 `4232` 经另一条公式得到 `2116`，用于焦点行程/位置归一化和分区表生成；它不是本次所问的上报速度。

## X1D 侧交叉验证

项目已保存的 X1D 1.25.0 原厂 FARM 动态镜头参数解析回放表明：回复里的 16 位速度值会乘以 100 后写入动态镜头缓存。把 EF-HX 的实际字段 `71, 71` 输入该原厂解析代码，离线执行结果为：

```text
model_slot = 18       # NEW LENS
speed_1    = 7100
speed_2    = 7100
```

因此，对“转接环连接 Canon EF 50mm F1.8 STM 时向 X1D 报告多少速度”的准确回答是：**线路原值 71，X1D 内部值 7100**。

如果机身另装了“以镜头报告速度的 70% 起步”的 AF 策略，那么首次低速阶段会使用 `7100 × 70% = 4970`；这是机身补丁的后续策略，不是 EF-HX 固件上报值。

## 可复核工具

运行：

```powershell
py -3 .\x1d\research\ef-hx-v104\analyze_profile.py "%USERPROFILE%\Downloads\EF-HX_PUB_V104.bin"
```

脚本会先核验文件哈希和头，再解析表项与上述两个速度尺度。它不会连接任何硬件。

## 证据边界

- 已验证：固件身份、52×18 字节表、4156 表项、静态换算结果、X1D 1.25.0 原厂解析代码的离线回放结果。
- 静态含义：`7100` 是机身内部的速度命令尺度，不能换算为物理速度，除非另做带时间基准和镜头位置反馈的实测。
- 未测量：EF 总线/XCD 总线时钟频率、镜头实际移动速度、从最近端到无限远的实际耗时。
