## 固定请求和返回值

[离线契约](../tools/farm_ram_contract.py)只能生成消息 `557`，不提供任意 ID、节点或参数。`libAppsMessaging.so`、FX3、SUC、FARM 四处定义一致：请求 `farm_get_ram_only_mode_req=0x22d`、回复 `farm_get_ram_only_mode_resp=0x22e`，各有一字节消息体。

| 项目 | 已核定义 |
|---|---|
| 语义请求 | `2d 02 08 01 00`：小端 ID，源 `usbhost=8`，目标 `farm=1`，零占位体。 |
| 回复语义 | `2e 02 01 08` 后跟一字节 `0` 或 `1`。 |
| USB 传输 | 控制 OUT `0x02` / IN `0x82`；按当前已核接口最大包长 `64/512/1024` 补零。本次实际为 `512`。 |
| 回复 `1` | FARM getter 报告 RAM 模式已生效。 |
| 回复 `0` | 未报告已生效；包括原厂中间状态，不能说明模式切换完成、存储可用或整机正常。 |

FARM `0x1e1c0c` 构造回复 `0x22e`，`0x1e1c30` 调用 getter `0x1e2c0c`。后者仅读取全局字节 `0x6c3918`：内部值 `0→0`、`1→2`、`2→1`、`3→2`，其他值返回 `0`。外层仅把 getter 结果等于 `1` 编码为回复 `1`，其余均回复 `0`。不存在从这一个字节还原全部内部状态的能力。

设置消息 `559/0x22f` 在另一分支调用 `0x1e1c60`；本工具不生成该消息。没有关闭 Demo、恢复默认值或修改相机设置。

## 正常往返路径

| 环节 | 固定版本证据 |
|---|---|
| FX3 接收电脑控制请求 | `0x400053e0` 读取目的节点；目标不是 FX3 `9` 时，`0x40005420→0x40005828` 取得既有 SUC agent，`0x40005444→0x40007870` 发送。 |
| FX3 传输条件 | `0x40007870` 要求已初始化缓冲及状态 `2`，长度不超过 `320`；本请求转发语义长度为 `5`。未就绪时返回错误，不由这条读取创建 Phocus 会话。 |
| SUC 接收和选路 | 原厂 FARM、FX3 UART 连接使用同一接收回调 `0x800f7a0`，交给 `0x800f644` 队列；主循环 `0x800fd38/0x800fd40` 按目的节点分派。目标 `1` 进入 `0x800fd78`，`0x800fd96` 调用 FARM 传输对象。 |
| FARM 注册和处理 | 初始化列表 `0x27c500` 包含 `557`；`0x1e263c→0x1e7fac` 注册回调 `0x1e2678`，它将消息送入 `0x6c37f0` 队列。消费分支 `0x1e2140…0x1e2148→0x1e227c` 调用已核 getter handler。 |
| FARM 回复目标 | `0x1e0a50` 把回复源设为 `1`、目标设为原请求源，因此本请求的回复目标为 `8`。 |
| FARM 返回 SUC | 回复先进入 `0x1e80d0` 正常路由队列；目的 `8` 在 `0x1e7780` 进入 `0x1ea49c`。该文件内嵌名称为 `suc_agent.c`，回复由其队列送往 `0x23cda0`。 |
| SUC 返回 FX3 | 主循环对目标 `8/9` 分派到 `0x800fdd4`，`0x800fde2→0x801acd0` 使用 FX3 传输对象。 |
| FX3 返回电脑 | 初始化回调表将接收处理绑定到 `0x40005230`；目标 `8` 在 `0x4000524c` 进入控制 IN DMA 函数 `0x400044a8`。 |

这些是原厂软件所安排的路由，不等于当前相机各段已工作，也不能把这条控制链与其他数据通路混同。

## 已核副作用和时间限制

- getter 本身读取状态；转发使用 USB、UART、RTOS 队列，正常及失败分支可能产生诊断记录。没有实测记录是否落盘。
- SUC 转发到 FARM 前调用 `0x800fbbc(2)`：若已有定时器则重置它，并通过 `0x8012e38(0x30a)` 拉低对应输出。其原厂名称为 `IMX IRQ Timer`，回调 `0x800f924` 再拉高。此处是正常通信信号的明确副作用；没有把它解释为整机复位。
- FARM 回复线程 `0x1e9c18` 可能等待既有 SUC 链路就绪。队列和既有传输协议也存在自己的等待。**主机 2000 ms 是本工具的停止预算，不是已证明的原厂最大往返时间。**
- 主机超时和关闭句柄不能证明机内请求或回复已撤销。晚到回复可能仍影响下一次控制 IN 读取；本次未发清队列、复位端点或持续读取来清理。

## Demo 与错误页的解释边界

固定 1.25.0 GUI 的 `DemoModeIndicator.qml` 绑定 `farm.ram_only_mode === Farm.RamModeRamOnly`。`ControlScreen.qml` 在 RAM 模式下隐藏整组存储卡状态行，所以看不到卡图标不等于物理卡枚举失败。日志导出另依赖 Storage 的当前卷和卷类型；未证明 RAM 标志必然阻止已有日志写卡，不能凭同时发生认定因果。

用户当前明确观察到持续错误 1000 挡住菜单；没有可用的菜单入口可据此关闭 Demo。本报告不要求用户再次进菜单、保存日志、重启或抢开机时间窗口。默认设置按钮在已核 QML 中调用 Configstore 重置，并不是上述 FARM getter/setter；其全部配置恢复效果没有在故障机验证。

下一步仍以正常只读诊断为限：有界检查当前格式的版本依赖、通信等待和晚到回复，再判断是否存在能区分链路状态的另一单项。未满足既有白名单、模拟验证和副作用条件前，硬件保持停止。错误根因和可行恢复操作均未确定。
