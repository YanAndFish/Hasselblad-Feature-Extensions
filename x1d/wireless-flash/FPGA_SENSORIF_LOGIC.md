# SENSORIF 的局部 FPGA 逻辑

记录日期：2026-09-10，北京时间。输入仍为官方 X1D 1.25.0 的 wedge PL 配置；来源、固定 SHA-256、数据库版本、CRC/ECC 边界见 [配置分区研究](FPGA_BITSTREAM_RESEARCH.md)。本轮没有新增实机请求、配置改写或安装。

**已把启动、模式和周期配置追到两路 I/O 输出，并在显式边界条件下复现行周期、帧周期脉冲；尚未对应到传感器真正开始积分的物理边沿。** 这里的寄存器名称来自 FARM 软件用途；内部节点名称来自公开器件数据库。不能用相邻位置、寄存器写入时刻或数据开始传输来代替感光时刻。

## 地址与数据对应

此前按 `AWADDR25` 追出的十六路选择继续向下，确认 `CLBLL_R_X51Y67 / SLICEL_X1 / BQ` 与 `CLBLL_L_X52Y81 / SLICEL_X1 / AQ` 分别来自暂存的地址位 14、15。它们不是已经证明的“读/写信号”。读、写地址各有实际输入暂存及汇合逻辑。

选择值 2 之后的三条分支分别按地址位 `[15:14]` 为 `01`、`10`、`00` 分流。主寄存器区对应 `00`，经 `CLBLM_R_X55Y77 / SLICEM_X0 / AQ`、翻转状态和采样、XOR 请求脉冲进入 `CLBLM_L_X58Y70 / SLICEL_X1 / BQ`。另外两条分支不能仅按寄存器数量称作读请求或写请求。

主区请求连接到地址及数据捕获寄存器的 CE；已逐项追通处理器 `MAXIGP0WDATA[18:0]` 的数据来源。数据位 0–5 位于 `CLBLM_R_X71Y61 / SLICEM_X0`，其中 4、5 使用 5FF 输出；其他位分布在邻近资源。这里确认的是数据连线，尚未仿真完整 AXI 事务或跨时钟握手。

局部低地址位对应如下：

| 地址位 | 主区捕获输出 |
|---|---|
| 2 | `CLBLL_L_X62Y71 / SLICEL_X0 / AQ` |
| 3 | `CLBLL_L_X62Y71 / SLICEL_X0 / BQ` |
| 4 | `CLBLL_R_X61Y71 / SLICEL_X0 / AQ` |
| 5 | `CLBLM_R_X65Y66 / SLICEM_X0 / AQ` |

低地址前级包含原始/暂存选择与 burst 地址运算。固定地址 burst 条件下，读写两侧四个地址数据路径都能化简为相应地址位；两个数据槽都给出同一地址时，后级数据选择保持该位，除两个控制位同时为 1 时清零。这个条件检查支持位编号对应，不能扩展为所有事务、所有周期的验证。

已识别偏移 `0x00`、`0x04`、`0x08`、`0x0c`、`0x1c`、`0x20`、`0x24`、`0x28`、`0x2c`、`0x30`、`0x34` 的局部 CE 译码。部分功能使用 LUT 反馈保持状态，不能只搜索 CE 漏掉这些寄存器。

## 启动位与模式位

主区中有以下两个相互独立的对应：

- **偏移 `0x18` 的模式位**：`CLBLM_R_X59Y67 / SLICEL_X1 / CLUT` 选择该偏移和接口请求/资格条件；`CLBLM_R_X59Y68 / SLICEL_X1 / CLUT` 实现保持或采样写数据。`CQ` 保存数据位 0，`CMUX` 经 5FF 保存数据位 1。与 FARM 把电子快门配置为 opmode 3 的用途一致。
- **偏移 `0x10` 的数据位 0**：`CLBLM_R_X59Y68 / SLICEL_X1 / DLUT` 的实际真值表要求低地址为 `0x10`、捕获数据位 0 为 1、局部请求脉冲为 1；随后该 slice 的 `BLUT → BQ` 还受另一个资格条件和经采样的抑制状态控制。不能忽略这些条件，或认为每次置位都会无条件启动。

在局部条件中把 `CLBLL_R_X61Y71 / SLICEL_X0 / BQ` 记作资格位，把 `CLBLM_L_X58Y68 / SLICEL_X1 / DMUX` 记作抑制状态。目前不把资格位直接命名为 WSTRB、写使能或总线有效，也不把抑制状态命名为“已曝光”。

后续有一条分支进入读回多路选择电路，不能沿它误认物理控制；另一条进入 `CLBLL_R_X61Y68 / SLICEL_X0 / BQ` 的有状态逻辑，并影响邻近状态/计数选择。这条才是继续核对电子快门同步的路线。

## 行周期字段与固定运算

FARM 把 `h_period` 写入 `0x4200000c`。主区对应的低地址译码位于 `CLBLM_R_X65Y69 / SLICEM_X0 / CLUT`；其 CE 下的十六个保存位已逐位追回 `WDATA[15:0]`，未发现位交换。

这些保存位送入 `CLBLL_L_X64Y68` 至 `CLBLL_L_X64Y72` 的 `SLICEL_X0` 进位链。根据实际 LUT、DI、进位初始化和连接，十七位组合结果为：

```text
result = (h_period - 54) mod 2^17
```

此处原始十六位 `h_period` 先零扩展；额外位保留该减法的符号/回绕结果。保存后的局部分析器已逐一计算全部 65536 个十六位输入，均与上述公式一致。例如软件基础值 2582 得到 2528，ADC 分支值 3206 得到 3152。

这只是配置中的整数运算。**54 不是实测延迟，不据此宣称提前一微秒、第一行开始感光或全幅已开始感光。** 后面还存在加法、选择、保存和状态条件，寄存器时钟与该结果的完整时序用途仍在核对。

## 分析器与复核边界

[research/fpga_logic.py](research/fpga_logic.py) 在已有布线对象上解码普通 LUT、触发器数据选择、CARRY4 和 F7/F8。它按配置保留 CE、SR、初始化、复位置位与时钟反相信息；没有使用 CE/SR 的 slice 按实际固定选择处理。未知资源和 RAM/SRL 保留为边界，未解输入不会默认为零。

`evaluate` 只计算组合逻辑。遇到触发器输出时必须由调用者显式提供状态，不自动跨过触发器或产生时钟。上述完整取值检查给定行周期保存位，只核对算术网络；不是完整状态机仿真或实机测量。

原语连接依据 [F4PGA 的 CLB 建模实现](https://github.com/chipsalliance/f4pga-xc-fasm2bels/blob/master/fasm2bels/models/clb_models.py) 复核，进位器行为同时核对 [Xilinx 官方 CARRY4 模型](https://github.com/Xilinx/XilinxUnisimLibrary/blob/master/verilog/src/unisims/CARRY4.v)；这些外部程序只作为源码阅读，没有执行。当前代码中的 F7/F8 解析支持也不能当作本次曝光路线已经实际经过这些资源的证据。字段对应、节点列表和本轮实际检查结果保存在 [研究证据数据](research/fpga-sensorif-evidence.json)。

## 时钟与两路 I/O 输出

新增 [research/fpga_clock_io.py](research/fpga_clock_io.py) 对实际选中的时钟、右侧 I/O PIP 做结构追踪。仅接受能对应 tile_type 实际端点的配置项；IN_USE、反相及 buffer 使能位不当作 PIP。双向 PIP 同时核对正反特征名。SING 等别名配置只在本 tile 的有效字范围内匹配，不借相邻 tile 的位补齐。

两路候选输出如下。`O0/O1` 是 IOB 内部输出数据端名称，不是已经核实的封装焊球编号或板级网络名称。

| 暂用名 | I/O 数据端 | 末级输出寄存器 | 前一级正沿寄存器 |
|---|---|---|---|
| A | `RIOB18_X79Y51 / IOB_O0` | `CLBLM_R_X71Y65 / SLICEL_X1 / AQ` | `CLBLM_L_X70Y70 / SLICEM_X0 / AQ` |
| B | `RIOB18_X79Y51 / IOB_O1` | `CLBLM_R_X71Y65 / SLICEL_X1 / BQ` | `CLBLM_L_X68Y70 / SLICEL_X1 / BQ` |

对应两个 OLOGIC 均选择 `OMUX.D1`，没有启用 ODDR/OSERDES 数据输出。A/B 的前级依赖经过 `CLBLM_R_X63Y72 / SLICEL_X1 / BQ`、`CLBLL_R_X61Y68 / SLICEL_X0 / BQ`，可追回前述偏移 `0x10` 的启动请求寄存器。这个依赖关系包含组合逻辑与有状态条件，不能把沿途寄存器数直接换算成固定启动延迟。

把已识别配置、接口捕获与五项外部状态保留为边界后，两路输出的局部依赖包含 135 个触发器、53 个 CLK 引脚位置。53 个位置都可追到 `CLK_HROW_BOT_R_X102Y78 / CLK_HROW_CK_HCLK_OUT_R1`；其中 133 个触发器为正沿，只有 A/B 末级两个为反沿，没有 latch。该分发路径继续通向 `RIOI_X79Y73 / IOI_ILOGIC0_O` 及 `RIOB18_X79Y73 / IOB_IBUF0`。路径相同支持局部同步采样建模，不证明实际频率或器件传播延迟。

另一项来自 `RIOI_SING_X79Y50` 的外部输入进入启动状态逻辑。当前未确定它和其他被截断外部状态的板级用途。时钟 buffer 的选择/使能、I/O 的输出配置及反相必须与结构路径分开核对；数据库中穿过原语的 `always` 连接不能独立证明电气透传。

## 显式条件下的周期复现

[research/fpga_cycle_model.py](research/fpga_cycle_model.py) 对给定状态先求全部下一状态，再同时写回，正沿后另求末级负沿。它不预测物理延迟、亚稳态或边沿之间的异步输入。所有边界必须显式给值，缺项会拒绝执行。

以下案例使用 opmode 3，在模型第 10 周期输入主区 `0x10 = 3` 的局部接口请求，下一周期撤去请求；此前显式保持三周期抑制。偏移 `0x00`、`0x20`、`0x24` 设为零，其他外部边界显式保持零。**帧行数特意使用合成小值缩短验证，不是相机真实配置，也不是完整 AXI 事务回放。** 表中数值均是模型周期数。

| h_period | 合成 v_period | 偏移 0x04 的输入值 | A 的下降沿间隔 | B 的下降沿间隔 |
|---:|---:|---:|---:|---:|
| 2582 | 8 | 40 | 2582 | 20656 = 2582 × 8 |
| 3206 | 9 | 80 | 3206 | 28854 = 3206 × 9 |
| 512 | 64 | 16 | 512 | 32768 = 512 × 64 |

三个案例中，A 的内部低电平持续 16 周期；B 的内部低电平持续 `h_period + 37` 周期。这里不把偏移 `0x04` 命名为脉宽寄存器，也不把这些内部电平持续时间称为传感器曝光时间。另一个 `h_period=2582, v_period=64` 的模型案例也复现 B 的 165248 周期间隔。

随后把帧行数改为官方全尺寸配置中的 `6320`，对两种行周期各运行超过两帧。下列结果来自实际执行的局部模型，其他外部条件仍是显式合成值，未读取实机配置；尤其偏移 `0x24=0` 只是案例输入，不能称为该拍摄模式的固定运行值。

| h_period | v_period | 执行周期数 | A 的下降沿间隔 | B 的下降沿间隔 | B 的内部低电平宽度 |
|---:|---:|---:|---:|---:|---:|
| 2582 | 6320 | 32644226 | 2582 | 16318240 | 2619 |
| 3206 | 6320 | 40533458 | 3206 | 20261920 | 3243 |

全部已记录的 A 下降沿间隔均为 `h_period`，低电平宽度均为 16；B 的下降沿间隔均为 `h_period × 6320`，低电平宽度均为 `h_period + 37`。为缩短这两次计算时间，[research/fpga_native_replay.py](research/fpga_native_replay.py) 将已有 Python 采样表达式的限定 AST 转为本机 C；它仍先求全部下一状态再写回。128 组随机状态的 256 次半周期结果，以及前述三个完整小案例的全部事件和最终状态，均与 Python 版本一致。完整配置、边界、检查与输出摘要见 [research/fpga-sensorif-full-rows.json](research/fpga-sensorif-full-rows.json)。这是电脑端的模型执行器，不是可以装入相机或 FPGA 的观察程序。

这支持把 A/B 分别作为**行同步、帧同步候选**继续研究。四项尚未追完整的外部状态分别固定为零或一，共 16 种组合，在各 5500 周期、同一启动条件下得到相同的前几次 A/B 跳变；这不覆盖这些状态随时间变化的影响。

模型生成前，以固定随机种子提供 128 组显式状态，对正、负两种半周期计算分别与原组合解析器比较，256 次对照无差异。实际保存的快照重新加载后，5000 周期事件及最终状态与先前内存分析一致；遗漏边界输入被正确拒绝。这些检查验证本次局部模型和保存过程，不是独立实机验证。

局部逻辑快照见 [research/fpga-sensorif-netlist.json](research/fpga-sensorif-netlist.json)，完整输入赋值、请求时刻、案例输出和检查记录见 [research/fpga-sensorif-replay.json](research/fpga-sensorif-replay.json)。均绑定原 PL 哈希及固定数据库版本，没有写回配置位或生成可加载文件。

尚须核对：A/B 的板级传感器网络名称、传感器对同步沿的定义、行编码与 SVR 的生效帧及内部行偏移。即使确认 A/B 就是传感器行/帧同步，也不能跳过这些信息直接标成第一行或最后一行开始积分。

## 外部输入条件及软件轮询位

先前来自 `RIOI_SING_X79Y50` 的输入经过 `CLBLL_R_X61Y68 / SLICEL_X0` 的 CQ、A5FF、D5FF 三次采样。偏移 `0x10` 的控制位 1、8、9 分别保存在 `CLBLL_L_X64Y67 / SLICEL_X1 / AQ、BQ、CQ`。当控制位 8、9 都为零时，后续 `CLBLM_R_X63Y68 / SLICEM_X0 / BLUT O5` 化简为常量 1，不再依赖该外部输入或其内部保持值。原厂电子快门启动写入 3 符合此条件；不能把这条输入当作已经找到的电子快门积分事件。

读取路径也已追至处理器读数据位 0、3。途中有保存寄存器和 SRL 队列，本轮核对的是数据来源，未模拟完整 AXI 读取。全局选择值 2、子区地址位 14/15 为零时，低偏移 `0x14` 对应：

| 软件状态位 | 保存该位的局部触发器 |
|---|---|
| bit 0 | `CLBLL_R_X61Y69 / SLICEL_X0 / DQ` |
| bit 3 | `CLBLL_L_X64Y64 / SLICEL_X1 / AQ` |

令 `a,b,c` 为 `CLBLM_R_X59Y69 / SLICEL_X1 / AQ、BQ、CQ`，`d` 为 `CLBLL_R_X61Y68 / SLICEL_X1 / AQ`。在未复位时，上述两个状态寄存器的下一值分别为：

```text
bit0_next = !(a | b | c | d)
bit3_next = (a & b) | (d & c & (a | b))
```

两式已穷举四个输入的 16 种组合核对。它们是控制状态的组合译码再保存，不是直接连接传感器积分输出。

在原 135 个触发器模型上加入这两个观察寄存器，使用合成 `h_period=512、v_period=64`，第 3000 周期提交 `0x10=0` 的局部停止请求：行脉冲继续到本帧末端后停止，控制状态在第 32781 周期回到上述四项全零，bit 0 在下一周期返回 1。bit 3 在该案例中保持零。这与 FARM 在电子快门停流分支等待 bit 0、跳过另一模式的 bit 3 等待相符；不表示已测得物理积分起止。

新增组合约束化简方法使用 192 个输入组合与原组合解析器对照，无差异。具体节点、输入顺序、观察寄存器、停止案例和检查见 [research/fpga-sensorif-status.json](research/fpga-sensorif-status.json)。

### 四个状态位的启动与停止对照

位 1、2 的读数据来源现也已沿 SRL 数据输入、全局选择值 2 和局部低地址译码追通。bit 1 最终来自 `CLBLL_R_X61Y69 / SLICEL_X0 / CQ`；bit 2 来自 `CLBLL_R_X61Y68 / SLICEL_X0 / BQ`，后者已经包含在原 135 个触发器模型中。这仍是选路核对，未模拟完整 AXI 事务。

在前述模型增加 bit 1 保存寄存器后，共 138 个触发器。使用相同合成 H512/V64、第 10 周期启动、第 3000 周期停止的输入，实际运行 40000 周期得到：

| 模型周期 | bit 0 | bit 1 | bit 2 | bit 3 |
|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 0 |
| 3 | 1 | 0 | 0 | 0 |
| 11 | 1 | 0 | 1 | 0 |
| 13 | 0 | 0 | 1 | 0 |
| 3001 | 0 | 0 | 0 | 0 |
| 32782 | 1 | 0 | 0 | 0 |

bit 2 在停止请求后一周期已经清零，此时行时序还会继续到帧末。因此它可以反映请求保持状态，不能用它的高电平表示完整采集忙碌区间，更不能把其边沿称为开始或结束感光。bit 1、3 在本案例中一直为零，不表示所有模式均为零。

新增寄存器、组合逻辑、完整显式输入及最终状态保存在 [research/fpga-sensorif-status-all.json](research/fpga-sensorif-status-all.json)。本次仅运行电脑端离线模型，没有新增相机读取、装载或物理感光测量。

## 偏移 0x24 对行、帧周期的影响

软件来源已进一步接通：`0x1c3aa0` 读取传感器配置 `+0x74`，作为第五个参数传给 `0x213af4`；后者保存到 `0x2b1990+0x10`，再由 `0x2139c8` 写到 `0x42000024`。裁剪配置函数 `0x234578` 的一条分支在 `0x234770` 设置该字段；其模式判断 `0x21f9e0` 接受内部模式 8–11。无裁剪分支跳过该字段赋值，因此仍不能仅凭电子快门配置函数推定当前字段必为零。

[research/sensor_mode6_config.py](research/sensor_mode6_config.py) 随后在隔离内存中实际执行了完整 `0x22f9f0` 的模式 6 分支及其原厂内存复制、清零和寄存器缓冲函数。给 `+0x74` 预填 0、1、255、`0x12345678` 四个合成值，返回后均原样保留，该字段没有被写入；同时 H2582、V6320、滚动模式标志和返回成功均通过核对。最后一个值只是用于发现意外覆盖的合成哨兵，不是有效相机参数。每例执行 751 个不同指令位置，执行仅允许已审核函数，写入仅允许合成配置、寄存器缓冲和栈；代码页不可写，没有映射硬件寄存器。截断固件和三类无效合成输入均被拒绝。此结果不证明上游从未清零或当前机身值非零，只确认不能把该函数视为每次都重置此字段。

在原 135 个触发器模型中，只改变该偏移的显式输入，保持 opmode 3、H512、其余配置和启动条件一致，得到以下结果。数值仍为模型周期，不是实机时间。

| 合成 V | 偏移 0x24 | A 的下降沿间隔 | B 的下降沿间隔 |
|---:|---:|---|---:|
| 64 | 0 | 512 | 32768 |
| 64 | 1 | 512、513 | 32769 |
| 64 | 54 | 512、513 | 32822 |
| 64 | 63 | 512、513 | 32831 |
| 64 | 64 | 513 | 32832 |
| 64 | 255 | 513 | 32832 |

这六例表明，该字段能让部分行增加一个周期，从而延长一帧；不能把所有配置的帧长都固定写成 H×V。上述案例的帧间隔符合 `512×64 + min(偏移值,64)`，此处只报告已执行案例，不把该表达式扩展为所有模式的公式。局部依赖中该偏移有八个输入位；另六例采用 V8，包含输入 511、512、600，结果符合局部模型只消费低八位的边界定义，不能用这些越过八位的输入替代真实总线写入验证。

十二例中，第一个 A 下降沿都在周期 20，第一个 B 下降沿都在周期 16，局部启动请求仍在周期 10。这说明本次参数变化未移动模型中的首个候选沿；不说明它就是第一行复位结束，更不是实测的固定启动延迟。

两个本机 C 回放均编译、运行成功；V8/偏移 1 的完整 24000 周期还用 Python 采样模型复核，405 条观测变化和最终全部状态一致。输入、源码哈希、来源地址和结果见 [research/fpga-sensorif-offset24.json](research/fpga-sensorif-offset24.json)，对应本机回放源码为 `build/fpga-offset24.c` 与 `build/fpga-offset24-v64.c`。本轮没有相机请求或安装。
