# 半按快门发送功率更新

## 电子快门条件提示（r4）

按用户本轮实拍反馈新增屏幕提示：引闪总开关和同步开关开启、使用电子快门时，若不在 M 档，或名义快门时间不在 250000–500000 微秒（含边界），显示“电子快门引闪：请用 M 档 / 快门设为 1/4–1/2 秒”。无效曝光参数也显示提示；机械快门、关闭引闪、休眠、回放及启动遮罩期间不显示。提示没有触控/按键处理，也不修改曝光、无线同步、功率发送或原厂补偿。

这是用户指定的使用条件提醒，不是新验证出的硬件能力边界，也不等于已经证明 A 档必然失败。现有电子同步算法以 FARM 观察器实际曝光为准，仍保留原来的时序边界；本轮不扩大或改写算法。只在后屏加入提示，EVF 尚未加入。

`ElectronicFlashHint.qml` 的 256 组状态与边界检查、现有 36 项半按门控检查、设置行检查和 ARM32 构建通过。r4 以已装 r3 为基线，仅更换封装后的界面资源；打包器强制确认 GUI 原生库和无线加载器哈希不变，完整原声音频及事务文件也保持不变。已持久安装一次，安装器返回 0；独立回读确认清单和四项载荷一致、根分区只读、五项原厂服务 active。见 [r4 安装回读](build/persistent-r4/installation.json)。尚待用户重启后的提示显示验收；未自动触发拍摄或闪光。

本轮用户报告半按功率更新、手动试闪可用，但部分拍摄不闪。回读的时间线包含 12 次准备请求及成功回执，11 个电子拍摄编号中有 9 个接受了同步事件；发射完成记录既有成功也有未成功，可能包含取消，不能等同于灯端确认。原有探针没有记录曝光时间、曝光模式及具体取消来源，不能据此归因于 A 档。原始本地证据为 `build/flash-failure-timeline.tsv` 与同名 JSON 摘要，不包含设备标识。当前运行 GUI 已匹配 r3，拍摄音频日志出现正常播放结束及现场恢复，但最终声音听感仍以用户确认准。

最新音频修正候选为 `build/persistent-r3`：以已装 r2 为基线，只替换 GUI 扩展以补齐音量和扬声器处理。打包时验证原菜单资源明文和半按 worker 不变，直接保留原封装资源、加载器和完整原声。参见 [失声修正说明](../../shutter-effects/README.md)；安装/重启结果以本版本 `installation.json` 为准，构建通过本身不代表设备验收。

本版已按用户明确授权持久安装一次，安装器返回 0。独立回读确认完整清单及四项载荷哈希通过、根分区只读、五个原厂服务 active，动画与声音模式仍为 2。见 [r3 安装回读](build/persistent-r3/installation.json)。尚待用户正常重启，确认新版运行与实际拍摄声音；临时诊断试听确认不代替重启验收。

适用范围：第一代 X1D-50c，官方 1.25.0，以及本地已安装的 Ciallo R6 基线。电子、机械快门共用已有半按事件和无线功率发送链路。新增引闪设置“半按快门发送功率更新”，默认关闭；这不是原厂功能，也不改变原厂测光或曝光参数。

## 行为

- 关闭时保留原有流程：分组编辑和试闪各自发送功率，按快门只准备同步引闪。
- 开启时，真实半按第一次到达后提交当前可见分组的功率批次，包含列表内关闭组的 OFF 状态。持续按住不重复发送；无线未连接、总开关关闭或上下文无效时不发送。
- 半按不触发拍摄或闪光。松开且尚未全按时取消剩余批次并恢复同步波形；已经发出的无线数据不能撤回。
- 全按立即调用原厂曝光入口，不等待功率回执。半按已准备的任务通过原有 `queueSync` 接入本次同步，不在全按时重复发送功率。没有有效半按任务时沿用原有仅同步请求。
- 半按后测光改变快门时间不取消已经提交的功率批次；全按使用最新名义曝光参数。电子快门同步计算仍使用原观察器实际曝光参数，机械快门仍使用原校准表。这里不进行 TTL 运算，也不按测光自动改变分组功率。
- 模式切换、上下文失效、断连和关闭该开关会取消尚未全按的准备。已开始的原厂曝光不被取消。
- 半按后立即全按仍可能来不及发送全部功率。既有策略会拒绝未就绪时到达的同步事件，不把它缓存后补成迟到闪光；新功能不能承诺任意手速、分组数量和无线状态下均完成引闪。

## 持久化与版本隔离

开关用现有私有设置目录内独立的 `halfpress-power` 文件保存，仅允许属主读写、单链接、两字节布尔值与换行。缺失或不合法时默认关闭；采用 `QSaveFile`、文件同步和目录同步，旧 `settings.bin` 格式不变。写入失败通过设置行显示错误，不假装保存成功。

`integrate.py` 对已装 R6 的资源和入口做计数为一的锚点替换，另行生成 worker 策略。正式源的默认策略不被改写。`build.py` 只写本模块 `build/`，保留此前启动稳定性修复，只替换 worker 对象。签名包只更新 GUI 资源、GUI 扩展和加载器三个载荷；保留已确认的 1.237 秒原声音频、相机事务修复、原厂文件和原设备授权集合。
