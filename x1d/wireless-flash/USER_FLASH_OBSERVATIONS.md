当前使用已安装的 GFS2 无线引闪版本，讨论的触发选项为“B 路同步已发生”。延迟均指界面设置值。

## 最新确认的观察

用户重新固定电子快门曝光时间为 **1/4 秒**，以“照片中第一次出现闪光亮条”为判据，确认 **B 路同步后的最低延迟为 60 ms，且表现稳定**。这是用户实拍确认的界面延迟值；未扩展到其他快门值，也不直接解释成传感器物理起始时间。

用户随后补充：电子快门曝光时间 **1/5 秒**，B 路同步后延迟 **111 ms** 出现第一条闪光亮条。本条尚未单独说明重复测试的稳定性，不沿用上一条的稳定性描述。

用户随后补充：电子快门曝光时间 **1/6 秒**，B 路同步后延迟 **160 ms** 出现第一条闪光亮条。本条尚未单独说明重复测试的稳定性。

## 固定 290 ms 延迟的补充观察

用户随后重新明确：B 路同步后延迟固定为 **290 ms** 时，电子快门 **1/4 秒或更快**，画面上方都有亮边；用户描述为“快门越快，亮边向下扩展就越大”。此处按原意保留画面现象，不擅自将“亮边向下扩展”解释成曝光带宽度、边界移动或扫描速度的变化。

这条观察与上述“首次出现亮条的最低延迟”是不同判据，不把 290 ms 写成首次出现的时刻。此前 560 ms 的记录仍待修正，不因这条补充而一并恢复为有效结论。

## 较长曝光档位的补充观察

用户补充：快门 **0.3 秒、0.4 秒、0.5 秒** 时，即使设置相同 B 路延迟，“一开始亮的那个时间”也对不上。先保留该实拍差异，各档位尚无新的具体延迟数值。用户据此提出“后面都是单独计算”的解释；该解释与实际内部算法的对应尚未验证，不将其写成源码已确认的事实。

用户继续试拍后补充：**0.3 秒、0.4 秒、0.5 秒** 这三个快门档位，其所判断的“快门完全结束”对应 B 路后的延迟约为 **860–870 ms**。作为用户根据闪光亮区判断的近似结束位置记录，不写成独立测量的硬件结束时间；用户据此提出这些档位可能分组，分组机制尚未确认。

用户决定到此停止外推：更长曝光通常用不到，不继续猜测或测试。用户提出后续可能按一整档（曝光时间相差一倍）形成类似分组，此项仅为未验证设想，不据此生成更长曝光的延迟表或自动补偿规则。当前保留的实拍分组仅为上述 0.3/0.4/0.5 秒三档。

## 用户指定的暂定时序估算

对 **1/4 秒** 电子快门，用户将 B 路之后约 **290 ms** 暂作“开始逐行结束曝光”的位置，并明确要求将最后一行结束暂按 **570 ms** 估算。两者相减得到约 **280 ms** 的扫描跨度。570 ms 是用户指定的估算值，不是新测量结果；此前 560 ms 只表示底部还出现最后一点亮带。

若进一步假设每行曝光持续 250 ms、上述两个结束点对应首尾行，则反推首行开始约为 **40 ms**，末行开始约为 **320 ms**。这些都是在该暂定模型下的算术推算，不等于已测得的传感器物理边沿，也不改动程序补偿。

## 全幅照亮的实拍确认

用户明确确认：**电子快门 0.5 秒，B 路同步，延迟 580 ms，全部照亮**。前一条语音转写有歧义，已经通过用户再次回答消歧，以“全部照亮”为准。这是当前测试条件下的成功实拍点，不据此确定全幅窗口的起止边界或其他快门档位的适用性。

用户继续确认同一 **0.5 秒电子快门、B 路同步** 条件：延迟 **590 ms 也全部照亮**；延迟 **600 ms 正好出现少量黑边**。因此目前已确认 580、590 ms 两个成功点，以及 600 ms 的黑边现象；不把未测试的中间数值或更早延迟一并标为通过，也不推定黑边方向。

用户继续同组试拍确认：**延迟 880 ms 仍有亮边**。因此对当前 0.5 秒条件，此前“860–870 ms 已完全结束”的估计被新观察修正，不能继续作为完全结束的已知值；亮边完全消失的延迟尚未确定。不将这项修正自动推广到 0.3/0.4 秒档。

用户进一步确认同一 **0.5 秒电子快门、B 路同步** 条件：延迟 **888 ms** 时仍有微弱亮边，宽度目测约 **十几个像素**。保留为用户目测描述，未读取照片核量；尚未观察到亮边完全消失的延迟。

用户随后将当前 **0.5 秒** 条件下亮边完全消失的位置暂估为约 **892–893 ms**。这是依据 888 ms 仍残留亮边提出的估计，尚未明确报告在 892 或 893 ms 实拍确认完全消失，不记为已测边界。

**最新取值决定：**用户表示不用太精确，并将刚才口述的 880 ms 明确更正为 **890 ms**，后续粗略估算统一使用 890 ms，替代上一条 892–893 ms 的暂估取值。890 ms 仅作为用户选定的近似计算值；仍保留 880 ms 有亮边、888 ms 有约十几个像素亮边的实拍事实，不称为精确的完全结束时刻。

用户补测同一 **0.5 秒电子快门、B 路同步** 条件：延迟 **595 ms、597 ms 均全亮**；结合此前 **600 ms 出现少量黑边**，用户决定开始出现黑边的边界粗略按 **600 ms** 计算。实际已测试的边界夹在 597–600 ms 之间，未报告 598/599 ms 的结果。与用户选定的末端近似值 890 ms 相减，得到 **约 290 ms** 的扫描跨度估算。

**用户最终指定的计算参数：整幅扫描用时统一取 290 ms。** 后续估算采用此值，替代此前 280 ms 或 290–300 ms 的暂估口径。这里记录的是扫描用时，不是速度单位；作为用户指定的近似计算参数使用，不据此自动修改机身补偿，也不升级为所有模式下的精确实测常量。

**1/4 秒档的新实拍修正：**用户确认 B 路同步后延迟 **570 ms 仍有亮带**。因此此前将 570 ms 当作该档最后一行结束的估算已被新观察否定，该档亮带完全消失的延迟尚未确定。此前依赖该 570 ms 末端推出的 280 ms 扫描跨度及首尾行开始时间不再作为有效结论；用户后续指定的 290 ms 扫描用时仍是当前统一估算参数。

用户继续确认 **1/4 秒电子快门、B 路同步**：延迟 **590 ms 时还有最后一点亮带**。此为残余亮带的实拍观察，尚不记作亮带完全消失。

用户明确补充：上述 **1/4 秒、590 ms** 的最后亮带仅剩**几个像素**，无法再往后细测，不继续要求测试。后续粗略计算可将该档末端取 **约 590 ms**，同时保留仍有几个像素亮带的观察，不称为精确消失点。

**最新计算参数修正：**用户明确将**整幅扫描用时改为约 295 ms**，替代此前统一采用的 290 ms。对 1/4 秒档，以近似末端 590 ms 反推：**590 − 295 = 295 ms**，即开始逐行结束曝光的近似时刻为 B 路之后 295 ms。扫描用时和反推时刻在本次算式中恰好同值，含义不同；均按近似估算使用。
