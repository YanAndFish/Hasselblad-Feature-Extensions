# X1D 拍摄无线引闪

本模块延续本任务已获授权的机身无线引闪实现，施工目录固定为本模块；实机试拍和试闪由用户操作。

后续新增的“半按快门发送功率更新”见 [半按功率开关](halfpress-power/README.md)，同时支持电子、机械快门。该页单列新版本的构建和安装状态；下文保留早期各轮同步研究的验证范围。

## 当前状态

- [FPGA 同步版本](research/FPGA_SYNC_CANDIDATE.md) 已在用户手动重启后的相机上临时安装：独立 Qt 检查、文件校验、服务启动、两个 FARM 钩子和捕获启用位回读通过。安装后快照为自动关闭、延迟 0、增益索引 60、同步通道可用，未提交引闪。用户随后拔下 USB 自测；实际同步消息与闪光效果待反馈，代理未拍摄或试闪。
- 已装版本仅接入 B 路 FPGA 同步保持信号。旧四个软件通知起点已移除，但用户要求的 **FPGA 多时序选择列表尚未实现**；不能把其他已研究候选写成已经可选。
- 当前安装证据见 `build/fpga-sync-candidate/installation.json`；`build/installation.json` 指向同一版本，之前的安装记录保存在候选目录下。恢复必须先停止引闪、解除 FARM 两个钩子，再移除消息消费覆盖。

- [FARM 回复旁听候选](FARM_REPLY_OBSERVER.md) 已在机内通过独立 Qt 合成报文自检，其临时文件已清理。真实消息服务挂接与首帧感光对应仍待验证；尚未接入无线引闪。
- 最新方向已按用户要求转查 FPGA 曝光状态和中断链路，停止继续采集四条软件通知。已定位传感器启动写入、同步标记和像素计数，并核对中断用途；进一步解开原厂 Linux 内核，确认现有 EIM 驱动只提供数据传输，没有现成曝光状态接口，见 [LINUX_EIM_RESEARCH.md](LINUX_EIM_RESEARCH.md)。尚无可直接用于本功能的已验证曝光中断或可安装补丁，整体状态见 [FPGA_EXPOSURE_PATH.md](FPGA_EXPOSURE_PATH.md)。

- 本轮接回 USB 后，原引闪常驻服务为 unknown、原厂 GUI 为 active，旧临时目录不存在。当前没有重装引闪程序；下面保留的是此前安装记录，不能当作当前仍在运行。此次没有测量通知到驱动提交或实际无线波形发出的延迟。
- 用户于 2026-09-10 试用常驻版本后反馈第一个起点仍不可靠，要求接入另外三个起点。三处静态位置已再次核对；原厂尚无可直接订阅的对应事件，临时 FARM 装载、代码缓存同步和恢复入口仍未解决，后三项尚未接通或安装。这三处的核对没有发送相机请求，详见 [PHASE_EVENT_RESEARCH.md](PHASE_EVENT_RESEARCH.md)。

## 此前引闪版本的安装记录

- 此前常驻版本已装入相机：文件校验、Qt 加载和无参数通知接收器检查、正常驱动标记读回、原生界面启动均通过。随后只读状态确认当时常驻程序与界面均为 active；自动开关已由用户开启，索引已调到 10，软件记录两次请求成功返回、零失败。这里不把驱动成功返回当作闪灯实际闪光，也没有测量物理时序；代理未试闪或拍摄。
- 已安装版本按此前要求先接第一个起点“曝光开始通知”。不检查电子快门开关，机械快门收到同一通知时也按相同路径引闪。
- 原生无线设置页保留四个起点；后三项灰显并标明“待接入”。延迟仅保留加减和步长切换，另有单次试闪按钮；按用户要求删除数字键盘和独立 `+1 ms` 按钮。
- 当前修正版保留单次试闪按钮的 190 单位宽度，高度从 36 增至 80，增加按下变色和收到按键次数。按钮固定在底部，设置内容可上下滑动；最大速度、减速度、边界行为和按压延迟直接绑定原厂列表。
- 无线发射功率默认沿用已读回的增益索引 60。增强降低索引，减弱提高索引，每次调整 5；按用户要求将试用范围扩至 10–100，可恢复默认。此范围是界面试用范围，不是芯片规格或实测功率范围，索引不表示闪灯输出功率或 dBm。新版在设置时应用功率并完成读回，不在曝光后重复设置。
- 新版 `native/wireless_worker.cpp` 常驻接收原厂 DBus 曝光开始、结束和就绪通知并计时；GUI 只发送设置和用户按键。发射阶段通过预先打开的正常驱动 socket 提交一次固定请求，不再启动 `wl` 子进程。准备和释放阶段仍使用原厂 `wl`。
- 当前原生控制器通过 51 项离线检查。较早的 JavaScript 四阶段逻辑草稿通过 33 项检查；它不包含当前试用包的机内接入。
- 修正旧版 glibc 的重定位布局兼容问题后，初版已在机身安装成功：主界面启动、设置页编译、曝光通知订阅入口均通过，默认自动引闪关闭。未由代理进行拍摄或试闪。
- 用户拔下 USB 自测后报告单次试闪间歇漏闪、自动曝光引闪未见闪光，随后接回 USB。修正版改用标准 Qt 信号连接并加入按键、曝光开始、结束、就绪、自动排入、提交、失败、取消和繁忙跳过计数。移除无线子进程继承的 GUI 预加载环境；手动试闪不再被无关的结束或就绪通知取消，自动待发仍受拍摄结束和就绪事件取消。用户观察尚未确定漏闪原因，不把连接修改当作已证实修复。
- 最近一次引闪安装当时的状态与具体版本记录见 `build/installation.json`；编译通过与实际安装、实际闪光分开记录，关机后的临时状态不能从此前安装成功推定。最新被动观察器的采样和停止记录另存于 `build/event-observer-build/installation.json`。
- 修正版现已传入并通过机身文件校验、动态加载、界面启动、设置页编译和三个 Qt 信号连接检查。默认自动引闪关闭，实际闪光与自动引闪效果待用户复测；代理没有进行新试闪或拍摄。
- 用户已确认前一版按快门能自动引闪，但零毫秒延迟仍然偏晚；约两米距离下增益索引 50 或更小能有效引闪。以上是用户观察，不是物理时序测量或可靠距离标定。默认档位按用户原要求仍为 60。
- 当前快速入口在原已试用波形上添加预先准备状态；44 项 ARM 指令模拟检查通过，包括未准备拒绝、错误频道拒绝、重复单次调用、停止播放清理、发射阶段不访问整段波形端口、未引入此前挂起的计时寄存器访问。没有通过代理触发实机拍摄或试闪来验证新版。

## 旧通知版本的固定来源与起点（历史）

静态来源为官方 X1D 1.25.0。程序位置表示软件流程，不表示已经测量的物理感光时刻。

| 值 | 界面名称 | 静态位置及边界 |
|---|---|---|
| 0 | 曝光开始通知 | FARM 0x1c4318 调用 0x1c3810；后续准备仍可能失败 |
| 1 | 采集准备成功 | FARM 0x1c432c 调用 0x1c5e34，返回成功后走 0x1c4348；不等于全幅像素复位完成 |
| 2 | 传感器启动指令 | SENSORIF 在 0x21410c 调用寄存器写函数，返回到 0x214110；须限定本次电子快门调用 |
| 3 | 像素计数达到阈值 | FARM 0x1c4454 读取计数，超过 99 后进入 0x1c4464；每次曝光的计数归属仍需确认 |

当前仅第一个起点可选，延迟范围为 0–5000 ms，默认自动引闪关闭。时间从常驻接收进程收到原厂软件通知后开始计算；毫秒输入粒度不代表实测定时精度。采集结束、就绪通知、关闭功能和切换设置撤销尚未提交的延迟动作，同次曝光的重复通知不会再次引闪。

新版在打开本页、修改设置或开启自动时生成并完整校验波形，同时建立正常 `nl80211` 驱动通道并读回补丁标记，显示“已就绪”后才接受发射。已准备的同一波形可连续复用；曝光通知后的请求与原厂 `wl phyreg 40 b` 相同，但由常驻进程直接提交。仍有原厂串口消息、DBus、常驻进程调度和驱动等待；这不是硬件中断直发，也没有测得通知到空中发射的物理时间。

GUI 与常驻进程通过本模块权限为 0600 的本地 datagram socket 通信。设置使用会话和序号去重；单次试闪不重试、不排队补发，且不修改自动开关。故障关闭后，旧设置快照不能重新打开自动功能，须由用户再次操作开关。GUI 连接超过两秒未更新时关闭自动并释放准备状态。原厂消息服务不重启、不注入，常驻进程只订阅三个无参数通知，不请求照片或相机方法。

为确保预先校验的波形在等待期间不被普通无线操作覆盖，就绪期间保持本模块的 MAC 占用，普通 Wi-Fi 数据传输会暂停。自动关闭后退出本页、GUI 退出或断联、常驻进程退出及执行本模块恢复脚本时释放占用并清除就绪资格。开启自动后退出菜单仍保持就绪，以供拍照使用。未就绪时不排队补发，界面会提示本次未发射。

## 无线试验状态

已有临时无线固件曾使用户观察到单次闪光，但五轮结果为未闪、闪、未闪、闪、闪；不能据此认定稳定。当前方案为 CH 5、ID 5、D 组普通单次引闪，与热靴独立。原厂动态闪光修正不在本模块的修改范围内。

## 文件

- `ui/main_additions.qml.inc`：驻留状态与适配器接口。
- `ui/settings_additions.qml.inc`：无线页入口、四起点选择、延迟加减和步长。
- `native/rf_core.h`、`CodeTests/native_core.test.c`：当前原生单次触发、取消与严格事件协议的离线检查。
- `native/wireless_runtime.cpp`：Qt 原生属性桥和本地设置、按键通信。
- `native/wireless_worker.cpp`、`native/rf_receiver.h`：独立常驻通知接收、计时和 Qt 无参数 slot。
- `native/prepared_radio.h`、`native/netlink_radio.h`：设置阶段准备、直接驱动请求、就绪复用和退出释放。
- `native/rf_bridge.h`、`native/rf_netlink_wire.h`：严格本地消息和正常驱动协议；对应检查位于 `CodeTests/`。
- `native/netlink_probe.c`：仅查询驱动家族和补丁标记，无发射入口；机身接口名以本轮只读核验的 `wlp1s0` 为准。
- `firmware/prepared_flash.py` 与固定输入块：由校验绑定的官方 WLTEST/probe10 基线生成快速入口，只在本模块构建目录输出。
- `CodeTests/prepared_firmware.test.py`：在模拟内存中执行候选 ARM 指令，不访问相机。
- `build.py`：仅在本目录构建，绑定官方 GUI 与 Qt 库；显式要求动态重定位表连续，以兼容机身 glibc 2.22。
- `install-session.sh`、`restore-session.sh`、`release-radio.sh`：相机 `/tmp` 与 `/run` 中的会话安装、常驻进程退出释放和 GUI 恢复，不改永久系统文件，不触发试闪或拍摄。
- `controller.js`、`CodeTests/controller.test.js`：早期四阶段逻辑草稿，未连接当前原生运行路径。

## 使用与恢复

安装验证成功后，从机身无线设置页进入“无线引闪（实验）”，打开“自动引闪”，选择延迟后自行试拍。电子和机械快门使用相同逻辑。单次试闪按钮仅由用户按下时发送；程序返回成功只代表提交了请求，是否实际闪光由用户观察。

本试用包在相机关机后失效，需要重新安装。相机永久 GUI、原厂动态闪光补偿和照片文件均不在本模块修改范围内。

加载器兼容性依据：glibc 2.22 的 [dynamic-link.h](https://github.com/bminor/glibc/blob/glibc-2.22/elf/dynamic-link.h) 在立即绑定时合并处理 REL 与 JMPREL。初版 LLD 产物把 ARM.exidx 插在两者之间，其首项低字节 `0xa4` 与实机错误一致；构建器现验证两表连续。
