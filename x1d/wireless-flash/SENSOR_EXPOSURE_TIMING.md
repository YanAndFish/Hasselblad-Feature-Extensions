# 电子快门积分时机：已还原的配置与尚缺的物理对应

记录日期：2026-09-10，北京时间。用户最新明确：在本次曝光开始的第一帧闪一次即可，后续帧不再触发。当前据此寻找第一帧内可靠的积分参照，仍可使用第一行开始积分、最后一行也开始积分或可证实的清空结束，再加独立延时。这里不把“数据流启动”改称为“开始感光”。

**已确认电子快门走滚动曝光参数配置，并已在隔离模拟内存中运行原厂换算函数；FPGA 局部模型也已复现两路行/帧同步候选的周期，尚未证明可订阅的物理积分边沿。** 下文原始研究为离线结果；2026-09-11 新增的实机软件记录单列如下，不把模型周期当作物理测量。

## 2026-09-11 的软件实录

[GFP3 两点记录](FARM_SENSOR_CAPTURE_V3.md) 已记录用户手动电子快门 1 秒试拍：原编码函数输入为 1000000 微秒、N=3/R=4366；启动时软件配置为 H2582/V6320、周期修正字段为 0，N 仍为 3。相同启动点的软件寄存器缓冲却已被重新建模为 N0/R1，因此该缓冲不能代表本次曝光编码。这是特定试拍的实录，不固定其他拍摄或模式的配置。

准备窗口中发生两次匹配编码，记录只保留最后一次，不能据此声称两个调用输入相同或唯一配对。程序已解除并恢复两处原入口，832 字节载荷留到下次手动重启。它只记录编码和 SENSORIF 控制写返回，未观察 SPI 写完成、传感器锁存或第一行积分；计数器频率仍未核实。

## 固定来源

全部 FARM 地址绑定官方 X1D 1.25.0 wedge 应用：1808280 字节，装载基址 `0x100000`，SHA-256：

`317841f6f4dff599cda8c83f2b4912f78534db20e7690d0b14b0cd5f1b8c39ca`

传感器实现的来源字符串 `0x256e04` 为 `../src/sensor_imx161.c`。配置分发 `0x235758` / `0x2357fc` 按传感器 ID 选择 IMX161 的 `0x22f9f0` / `0x2305d0`。这不把其他 IMX 型号的数据手册、X2D 的闪光同步函数或当前机身未读取的配置当作本机事实。

## 从电子快门到滚动曝光配置

| 证据位置 | 已核对行为 |
|---|---|
| `0x1c3ef8–0x1c3f00` | 电子快门流程向 `0x1c3978` 传入内部捕获模式 6、SENSORIF 模式 3 |
| `0x21e5e8` | 创建传感器配置、整理曝光参数、选择控制模式，再应用传感器配置 |
| `0x22fb24` 起 | IMX161 全尺寸配置分支设置输入 8372×6304、有效尺寸 8272×6200，基础行周期 2582、帧周期 6320、14 bit |
| `0x22fcd4–0x22fcf8` | 内部模式 6 将配置字节 `+0x7d` 清零。不能只读此分支早先的初始值 1 就认定电子快门使用另一种曝光模式 |
| `0x23042c–0x230464` | 按该字节设置传感器寄存器，并计算基础帧曝光上限 |
| `0x21dbb8–0x21dc14`，关键分支在 `0x21dbd0–0x21dbd4` | 模式 6 绕过其他滚动模式的单帧时长钳制，允许后续换算跨帧曝光；确切跳转目标为 `0x21dc14` |
| `0x230644–0x230670` | `+0x7d == 0` 时调用 `0x233ac0`；同一路径日志明确称为 `Rolling shutter exposure-time` |

配置中的行周期还会受 ADC 设置影响：`0x230640` 调用 `0x22ef3c`；允许的全尺寸传感器模式中，当输入 ADC 参数为 2 时，`0x22f20c–0x22f214` 将行周期改为 3206，日志为 `ADC=2x, modified h_period_clks`。本轮没有读取当前机身实际选择，不能固定使用 2582 推算所有照片。

## 原函数怎样编码曝光时长

`0x233ac0` 使用输入曝光微秒数、配置行周期和帧周期。其整数关系为：

```text
L = floor(exposure_us × 54 / h_period)
N = max(0, floor((L − 1) / v_period))
R = clamp((N + 1) × v_period − L, 2, v_period − 2)
```

`N` 写入配置 `+0x98`，并经 `0x233a4c` 编入传感器寄存器缓冲的 `+2/+3` 低 12 bit；后述原厂日志将此项称为 SVR。`R` 编入 `+5/+6` 低 14 bit，相邻高位保留。函数返回原输入曝光时长，**返回值不是量化后实际曝光时长或测量结果**。

以下是运行原 ARM 函数得到的部分合成结果，帧周期固定为 6320。这些是参数编码，不能把 R 直接当作“启动后第 R 行开始感光”；尚缺传感器对同步信号、内部行偏移及参数生效帧的准确时序定义。

| 合成曝光时长 | 行周期 | SVR 编码 N | 行编码 R |
|---|---:|---:|---:|
| 1/4 秒 | 2582 | 0 | 1092 |
| 1/2 秒 | 2582 | 1 | 2183 |
| 1 秒 | 2582 | 3 | 4366 |
| 1/4 秒 | 3206 | 0 | 2110 |
| 1/2 秒 | 3206 | 1 | 4219 |
| 1 秒 | 3206 | 2 | 2117 |

离线复核程序为 [research/sensor_exposure_timing.py](research/sensor_exposure_timing.py)。先核对整份 FARM 哈希，只映射官方代码和合成 RAM，仅准许曝光换算、SVR 编码和已审核的原整数除法函数执行，没有用替身代替除法。代码页不可写，合成数据页不可执行；设置指令数量和运行时限。14 个合成案例实际通过，并检查相邻寄存器位保留、未修改其他寄存器缓冲字节、返回值及独立整数表达式；截断 FARM 输入被拒绝。

## 启动后的 SVR 清零

这里的跨帧分支门槛来自 `L >= v_period + 1`：H2582/V6320 时，整数微秒输入从 302238 开始产生非零 N；H3206/V6320 时从 375281 开始。因此 1/2 秒和 1 秒属于此分支，1/4 秒及更短不属于。这是固定配置的原函数编码门槛，不是当前机身读出模式实测，也不是要求用户必须采用这些曝光时长。

门槛前一微秒与门槛值的四个案例已实际运行原 ARM 函数核对，结果与该表达式相符；输入、源码哈希及下述消息链证据见 [research/sensor-svr-update.json](research/sensor-svr-update.json)。

电子快门流程 `0x1c4378` 提交 SENSORIF 启动后，紧接着调用 `0x1c7fdc`。后者在配置 `+0x98` 非零时，用 `h_period × v_period / 54000` 的整数结果再除二，建立或重设一个单次 RTOS 定时器，然后启动它。

定时器回调 `0x1c80ec` 输出 `Setting SVR = 0`，在 `0x1c8180` 调用 `0x235a24(0)`；IMX161 分支进入 `0x22f41c`，编码零并通过原有传感器配置消息更新相应两个字节。没有修改原行编码。

继续核对到：`0x22f480–0x22f48c` 向 `0x234c64` 传入模式 2、起始地址 2、长度 2 和缓冲 `0x6db2ea`。后者构造来源 FARM 1、目的 pwrctrl 2 的 `0x23` 请求，经 `0x1e8718` 等待 `0x24` 回复；固定消息名表 `0x29effc` 分别将两者命名为 `pwrctrl_spi_write_req` / `pwrctrl_spi_write_resp`。这是传感器寄存器写入消息链的静态证据，不代表回复时刻等于传感器锁存时刻，也没有执行该写入。

这里已能解释“跨帧曝光参数在启动后还会发生一次原厂更新”，但仍不能把这个软件定时器回调当成积分开始事件，也不能从名义节拍推导实测精度。两个基础配置的名义完整帧周期分别约 302.19 ms 和 375.22 ms；这是时序参数算术，**不是按快门到感光的延迟，也不是已测得的全幅同时感光窗口**。

后续 [SPC 发送与回复复核](SENSOR_SPI_COMPLETION.md) 已执行原控制器 Thumb 代码：正常返回在底层发送路径之后，但某些字节错误可被外层忽略。因此成功回复仍不能独立证明每字节发送成功、参数锁存或积分开始。该异常仅在合成模型中出现，未在本次相机观察到。

## 与两个目标时刻之间尚缺什么

第一帧只闪一次是用户选择的目标行为，尚未安装或验证。后续实现需在本次电子快门启动时重新建立帧归属，只接受这个捕获的首帧参照并消费一次资格；取景脉冲、后续帧、重复事件不得再次触发，取消或退出捕获后清除待发状态。现有观察组件虽有一次性 armed 门控，仍未证明首帧的物理感光对应，也未接入无线发射。

当前与用户一起核对的候选如下，优先研究前两条：

| 候选 | 已有依据 | 还缺的对应 |
|---|---|---|
| 帧同步沿 B | FPGA 局部模型复现每帧一次的脉冲；首个候选沿在已执行的周期修正参数变化下保持同一位置 | 本次有效曝光对应哪一帧、哪个沿，以及相对第一行复位结束的偏移 |
| 行同步 A 加曝光行编码 | 每行脉冲和原 ARM 曝光行数换算均已复现 | 行数应从哪个同步沿起算、传感器内部行偏移和有效行范围 |
| 传感器清空／复位结束 | 作为更直接的目标事件继续寻找 | 尚未找到能准确代表它的独立信号；不能标记为已发现候选引脚 |

`0x214110` 的“启动命令提交后”位置只作为软件时间参照。其上下文门控观察组件已实际装载、取得记录并解除；没有把它升级为感光起点，也没有恢复此前停用的粗粒度软件通知。

1. 第一行开始积分：需要确定传感器同步沿、行编码、SVR 和启动状态如何共同决定本次有效帧的第一行复位结束。现有函数调用顺序和参数编码没有给出完整物理对应。
2. 最后一行也开始积分：除了第一行时刻，还需要有效行范围与复位扫描的准确跨度。读出同步标记及数据到达不能自动替代此信息。
3. 用来全幅引闪时，还必须保证第一行尚未结束积分；“最后一行已开始”本身不保证此时全幅仍同时积分。当前没有据此要求用户改曝光参数或进行新试拍。

SENSORIF 状态与中断核对见 [FPGA_EXPOSURE_PATH.md](FPGA_EXPOSURE_PATH.md)。原厂 FPGA 配置分区也已独立分离并解析，见 [FPGA_BITSTREAM_RESEARCH.md](FPGA_BITSTREAM_RESEARCH.md)。最新 [SENSORIF 局部逻辑](FPGA_SENSORIF_LOGIC.md) 已把启动请求追到两路 I/O，并在 opmode 3、显式边界和合成小行数条件下复现 `h_period`、`h_period × v_period` 的重复周期。这为行/帧同步提供具体候选，但仍未补足上述传感器行编码、SVR 生效帧和内部复位扫描的物理对应。
