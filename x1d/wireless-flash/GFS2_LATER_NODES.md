# B 路之后的两个引闪节点

来源：官方 X1D 1.25.0 FARM，SHA-256 `317841f6f4dff599cda8c83f2b4912f78534db20e7690d0b14b0cd5f1b8c39ca`。本文是离线候选实现与静态分析记录，不将官方输入直接称为当前机身运行事实。此前用户报告旧 B 路版本实拍能引闪，不代表本候选已经安装或实拍通过。

## 界面及行为

保留 B 路同步，增加用户指定的两个选项，不增加 A 路或自动扩展其他选项。

| 选项 | 实际采样点 | 含义及限制 |
|---|---|---|
| B 路同步已发生 | 原 `0x1c4380` | 已清旧标志后检查 FPGA 状态 bit 10，仍是原单次检查位置 |
| 拍摄进度读数达到设定值 | 原 `0x1c4458`，进度函数返回之后 | B 确认后转发严格增加的原厂读数，由接收端比较用户门限 |
| 原厂正常请求停止前 | 原 `0x1c44f4` | 在原厂正常停止调用之前采样；超时停止不走此入口 |

每次拍摄只按选中的一个节点排入一次引闪。选中进度后显示加减按钮，门限 0–100、步长 1，第一次读数达到或越过门限即取得资格；不要求精确相等，也不把数值标为百分比。门限 0 表示 B 确认后的第一次有效进度读取。未确认 B 不产生其后续节点；设置变化取消当前拍摄资格，避免切换节点或降低门限后补发。三个选项共用原有 0–5000 ms 延迟，从 Linux 接收到该节点消息的时间计算。原厂动态闪光修正未改。

两个新增入口保存通用寄存器和状态寄存器，恢复后执行被替换的原厂指令。使用原消息队列的零等待投递，B/正常停止各最多一次尝试，进度只发送严格增长值。原厂返回值为左移一位后的偶数，达到 100 后不再发送进度，因此每次拍摄最多 51 条进度消息；重复、回退和达到退出门限之后的值不重发。投递失败不重试该读数，若之后更大的有效读数仍达到门限，可在该更晚节点取得首次引闪资格，因此不是原始门限的精确物理时刻。没有新增拍摄、对焦或硬件轮询调用。进度节点和停止节点会读取既有状态与计时器用于记录，不把这些读取解释成新的 FPGA 边沿。

## 进度和中间事件核对

`0x214520` 通过原厂读取函数读取 `0x42008010`，将值左移一位后返回。电子快门循环在返回值不大于 99 时继续，达到 100 或以上才离开；不能据此将值命名为行数或曝光百分比。该地址位于另一子区，当前 SENSORIF 局部模型尚未覆盖其内部计数来源。

离开进度循环到正常停止入口之间的直接调用包括日志级别判断及字符串/日志处理；`0x236a14` 检查普通内存中的日志阈值，没有访问 FPGA 寄存器。这里未发现另一条明确的传感器积分事件读取。

已知而未接入界面的 FPGA 变化仍包括 B 电平恢复、后续周期脉冲、停止后请求保持位 bit 2 清零及帧结束后空闲位 bit 0 返回。它们不是本次新增的两个 CPU 节点。先前局部模型显示请求位可在时序真正停下之前清零，不能拿它当感光结束。bit 1/3 在部分显式案例中未变化，但不能据此认定所有模式都无事件。

因此尚不能声明已列尽 B 后所有 FPGA 事件，也尚未找到可命名为“最后一行开始感光”的已验证节点。下一项内部研究是 `0x42008010` 的读回来源、计数使能及清零条件。当前三个采集点仍限定电子快门，机械快门未接入。

- 相机 ARM 库和 worker 编译链接通过，QML 资源已打包。机内 Qt 检查、界面显示和实拍尚未执行。
