## 原单次准备版记录

本轮依据用户“好，可以试试”“A路的也一起加上吧”及“多加点你觉得可能的FPGA上的信号”实施。程序只在本任务授权的 `x1d/wireless-flash` 内生成；没有 Git 操作。用户自行拍摄，程序不替用户操作快门、对焦或单次试闪按钮。

| 选择项 | FPGA 状态条件 | 解释 |
|---|---|---|
| A 路首次同步 | `0x42000014` bit11 | 已确认清旧值后，本次首次观察到 A 保持位置位 |
| B 路首次同步 | 同寄存器 bit10 | 已确认清旧值后，本次首次观察到 B 保持位置位；默认选项 |
| 启动保持置位 | bit2 从 0 到 1 | 控制请求保持，不等同于物理积分开始 |
| 退出空闲 | bit0 从 1 到 0 | 控制状态离开空闲 |
| 状态 1 置位 | bit1 从 0 到 1 | 状态组合译码；物理含义待确认 |
| 状态 3 置位 | bit3 从 0 到 1 | 原厂停止流程会检查此位；物理含义待确认 |
| 返回空闲 | 本次先观察到退出空闲，再见 bit0 从 0 到 1 | 较晚的控制状态对照，不称作曝光结束沿 |

每次正常请求同时记录全部候选位。A、B 等位可能在同一次采样中出现，报文保存同一时间戳和原始状态，不人为制造沿间隔。状态 1、3 未发生可观察变化时不产生对应事件。

界面位于原 Wi-Fi 设置页的“机械快门 · FPGA 试验”。每项独立保留本会话延迟，范围 0–5000 ms，步长 1/10/100 ms。先选信号和延迟，再点“准备本次引闪”，由用户拍摄；一次准备最多提交一次无线请求。改信号或延迟会撤销旧资格，发送失败不重试。采集结束会取消仍未提交的延迟。无线沿用本机此前试验的 CH 5 / ID 5 / D 组及既有预生成波形，原厂镜头动态补偿不改。

延迟从 Linux 收到消息的时间计算，包含此前的 FARM、消息传输和调度迟滞。0 ms 表示不再额外等待，不是物理零延迟。这里没有测得物理闪光、曝光窗口或计时精度。

来源固定为官方 X1D 1.25.0：FARM SHA-256 `317841f6f4dff599cda8c83f2b4912f78534db20e7690d0b14b0cd5f1b8c39ca`，PL SHA-256 `8df07fecb3ccb1227ea696a19b52622be124426cb493724eea1f5705c7245a30`。镜头原厂补偿研究另见 [LENS_FLASH_SYNC_RESEARCH.md](LENS_FLASH_SYNC_RESEARCH.md)，没有把共享镜头包当作当前镜头实机镜像。

FARM 使用五处原厂调用位置：`0x21409c` 的启动前控制写、`0x21410c` 的正常启动控制写，以及 `0x213e60`、`0x213ef8`、`0x2143e4` 的既有状态读取。启动入口严格匹配 `2a/21d → 0x1c4eac(source=3, mode=0/1) → 0x213fcc(cmd=0)`、两层返回地址、参数及栈帧关系。只有这个入口把原清零值加上已验证的独立保持位清除 bit6；下一次原厂控制值 3/7 保留。后续状态直接复用原厂读取的返回值，不添加等待循环。新的任意传感器启动关闭上一采集窗口，结束读取也关闭窗口。编号表示普通请求，不冒充照片 ID。
