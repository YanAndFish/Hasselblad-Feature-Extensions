# 纯时序记录候选

用户明确更正为“先纯记录，不补偿”。已实现独立记录版本并完成离线构建，**现已完整临时装入相机**。它基于当前已装的芯片预准备、无持续诊断版本；只替换 Linux worker 和静态文件清单，不改变 FARM、FPGA、无线固件、波形、七个来源、用户延迟或一次请求资格。闪灯功率编码仍未接入。

## 记录内容和保存方式

开启自动引闪后，把记录写入 2048 条固定内存环。每条 72 字节，保存消息自身的采样计数、观察器收包时间、worker 处理时间、预设截止点、定时器回调、驱动提交前后及驱动回复。拍摄编号、观察器 epoch、选定来源、延迟值和驱动序列用于关联；配置事件还记录无线增益索引。满环覆盖最旧记录并明确累计覆盖条数，不声称数据完整。

**只有自动引闪关闭、没有待发截止点、无线操作空闲时才保存**到本模块临时目录内的 `timing.bin`。正常拍摄期间没有新增格式化、文件写入、进程或诊断线程。关闭后保存失败会通过现有状态文字反馈，不在后台反复写入。正常退出会走同样的关闭路径；强制断电或崩溃可能丢失尚在内存的记录。

增加了内存写入和驱动提交前后的时钟读取，实际额外开销尚未测量，不能承诺记录完全不影响时序。

## 可以计算什么

主机解析器 `analyze_mechanical_timing.py` 可导出 CSV 及分段摘要：

| 分段 | 口径 |
|---|---|
| 观察器 → worker | 两者同属 Linux 单调时钟，观察器纳秒按 worker 相同规则向下取整为微秒 |
| 预设截止点 → 定时回调 | 已获发射资格的回调相对原截止点的迟到量，按来源和用户延迟分开统计 |
| 驱动提交调用 | 提交系统调用前后时间差 |
| 提交 → 驱动回复 | 软件回复耗时，包含当前无线固件的启动后等待、清理和下一次准备 |

FARM 计数来自状态采样时读取的全局计时器，**不是硬件边沿锁存值**；它与 Linux 单调时钟尚未对齐，原值保留但不跨时钟相减，不输出伪造的“硬件到 Linux 延迟”。驱动提交和回复都不是实测射频起发或闪光灯发光时间。本候选不会根据记录调整截止点，也不会增加、延后或重试原有发射资格。

## 硬件中断可行性核对

新增 `mechanical_irq_inventory.py` 重建固定官方 X1D 1.25.0 FPGA 配置，核对 **16 条共享中断输入和另 4 条 CPU 专用中断输入**，而非只看原厂注册表。输入与处理器中断类别按 [AMD UG585 中断信号定义](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/Interrupt-Signals) 区分。

- 当前“退出空闲”状态的直接来源为 `CLBLL_R_X61Y69 / CLBLL_LL_DQ`，直接网络只有 10 个节点，没有到达 IRQF2P 引脚。这是直接布线结论，没有把它扩大成全部逻辑依赖均不相连的证明。
- 共享输入 5、14、15，以及 CPU 专用输入 16–19 在这份配置中接地。接地是当前配置事实，不等于已有可供软件开启的曝光中断，也不自动证明资源可安全占用。
- 已找到的预闪支路接入共享输入 12，对应 GIC 88，并含持续高电平资格门控；不能直接拿来当所选状态变化的中断。

可研究的新路径是：在 FPGA 内从所需状态构造一次事件，接到经确认可用的中断输入，由 FARM 的短处理函数记录／通知。新增路径需要确定事件的物理含义、边沿或电平行为、屏蔽与确认方式、跨时钟处理以及不干扰原厂配置的逻辑布线修改；当前没有已构建或可安装的中断实现。

即使这一段改成中断，FARM 到 Linux 再到无线芯片的传递仍存在。现有无线驱动调用带有锁和等待，不能直接搬进硬中断处理函数；这是已反汇编的驱动事实，也符合 [Linux 中断上下文限制](https://www.kernel.org/pub/linux/kernel/people/rusty/kernel-locking/c557.html)。不能把“取得中断”当作端到端引闪已经稳定。
