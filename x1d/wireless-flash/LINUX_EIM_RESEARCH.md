# 主处理器并行总线的实际用途

记录日期：2026-09-10，北京时间。延续 FPGA 闪光同步研究；本轮没有相机请求、寄存器操作、试闪或拍摄。

**已核实原厂 Linux 内建 EIM 驱动，但它没有现成的曝光状态读取或曝光中断接口。** 普通 `read` 固定拒绝；`poll` 查询 DMA 传输状态；唯一 `ioctl` 用于提交数据搬运。这个结果排除了“打开现有总线设备，就能订阅曝光边沿”的方案，不证明 FPGA 电路中没有尚未导出的同步信号。

## 固定来源与复核

输入来自官方 X1D 1.25.0 rootfs 中的 `./boot/zImage-3.14.28-1.0.0_ga+yocto+gf7d0ab5`。文件长度 3770184 字节，SHA-256：

`2ed302a02c37c40fbf43fe4074f8069c1be0e4f6cf53fb556ad4daf0ba4c1a0a`

本轮在主机内存中模拟执行该固定文件的独立 LZO 解压函数，未启动内核；28 个数据块的原有 Adler-32 全部匹配。得到 7235068 字节，SHA-256：

`4fefe290be2c10fc2ac2215e8f9d991ffe9e553c5a7df4541c63a4a6ca8be34f`

内核虚拟装载基址为 `0x80008000`。从内核自身的 kallsyms 恢复 44884 项，核对符号数、每 256 项的分组偏移和全部 256 个 token 索引。下文函数名来自该内核的符号表；不是仅凭字符串猜测函数。函数首部的 `__gnu_mcount_nc` 是编译时跟踪入口，不属于设备寄存器读写。

可重复的固定输入检查位于 [research/kernel_eim.py](research/kernel_eim.py)。该工具只接受上述 zImage 哈希，核对解压结果、符号结构与四处指令守卫，拒绝截断输入；没有 USB、物理内存、串口或设备文件访问代码。实际运行复核通过。Lzop 块布局另与 [Linux 3.14 解压源码](https://raw.githubusercontent.com/torvalds/linux/v3.14/lib/decompress_unlzo.c) 对照。

## 驱动接口

| 入口 | 固定内核地址 | 已核对行为 |
|---|---|---|
| `eim_read` | `0x8023ee6c` | 跟踪入口返回后，在 `0x8023ee80` 固定返回 `-13`，不读取总线数据。它不是待填写地址的通用寄存器读取接口 |
| `eim_poll` | `0x8023ef34` | 调用 DMA 通道的状态操作，状态为进行中时登记等待队列；否则返回 `0x104`。不查询 SENSORIF 同步计数。这里“非进行中”不能一概说成传输成功 |
| `eim_write` | `0x8023f39c` | 用互斥锁串行化；DMA 进行中则返回忙，否则把用户数据复制到已映射的总线窗口，一次最多 4096 字节。文件位置递增不代表硬件目标地址随之改变 |
| `eim_ioctl` | `0x8023f504` | 只接受 `0x40084501`；从用户复制 8 字节的地址、长度信息，建立分段 DMA 描述符并启动。不是提供任意 FPGA 地址的状态查询 |
| `eim_open` | `0x8023fd34` | 必要时申请 DMA 通道，并把设备实例放入文件私有数据。打开设备不是无状态的字节读取 |
| `eim_release` | `0x8023fe14` | 调用通道资源释放路径，再释放 DMA 通道 |
| `eim_dma_callback` | `0x8023fe94` | 唤醒等待者，释放两组分段描述符。这是数据搬运回调，未包含曝光事件识别 |

`eim_fops` 位于 `0x804d1554`，其中的读写、poll、ioctl、open、release 指针与上表一致；该表没有 `mmap` 处理函数。DMA 状态的命名与 [Linux 3.14 dmaengine 接口](https://raw.githubusercontent.com/torvalds/linux/v3.14/include/linux/dmaengine.h) 对照，具体分支以本机型原厂内核指令为准。

## 地址窗口不是传感器寄存器镜像

`weim_probe` 位于 `0x8023f858`：完成 WEIM 时序配置后建立名为 `eimbus` 的字符设备，另外申请并映射物理地址 `0x08000000` 起的 **4096 字节**，保存到实例 `+0x24`。映射在 `0x8023fa60–0x8023fa74`，供写入与测试图样路径使用。

DMA 描述符构造在 `0x8023f754–0x8023f7c4`：一组地址随待传数据偏移，另一组使用固定 `0x08000000`；完整段长度为 `0xfe00`。`0x8023f628–0x8023f6b0` 配置并提交 DMA，登记上表的回调。没有出现从 FARM 的 `0x42008000` 等地址到 Linux 的通用寄存器转换。

设备树声明 128 MiB 总线地址范围，与驱动实际映射的 4096 字节用途是不同层面的信息。不能由设备树窗口大小推导出整个范围都可读，也不能把 FARM 的 SENSORIF 地址加减一个常数后试读。

## 排除另一个同名计数器

内核还暴露 `counter_show`、`counter_store`、`testpat_show`、`testpat_store` 和 `testgen_store`。其 `counter` 是测试图样生成使用的 Linux RAM 变量 `0x807627e4`；`testgen_store` 在内存中生成递增字或固定图样，再复制到总线窗口。它不是传感器帧计数、曝光计数或硬件时间戳。本轮没有调用这些接口。

## 对后续实现的影响

1. 不将 `eimbus` 的 `poll` 接入现有无线引闪程序；它代表的条件不同，也不是新的曝光起点。
2. 保留“研究 FARM 内部真正的同步条件，并找到可恢复的事件导出路径”这一方向。仍须解决事件含义、临时执行区、缓存同步和恢复；本轮没有形成可安装补丁。
3. 原厂读寄存器包装 `0x23899c` 也不是无条件的被动读取：当 PL 未启用且请求地址位于其外设区间时，会先申请资源 23，再读取并释放。不能为获取快照而未经核对地唤醒 FPGA。
