# FPGA 曝光状态与中断路径核对

记录日期：2026-09-10，北京时间。用户已明确停止继续采集四条软件通知，要求转查 FPGA 链路；独立通知观察器此前已正常停止，本轮未重新启动。

**本轮结果是离线定位，不是已接入的引闪功能。** 已定位 SENSORIF 的启动写入、同步标记计数、像素计数，以及 FARM 的中断注册和分发路径。目前仍未建立“本次曝光的物理同步事件 → 无线波形”的可用通路，没有可供安装的 FPGA 同步补丁。

后续按用户明确的“第一行开始积分或最后一行也开始积分”目标，已确认电子快门最终使用滚动曝光配置，并在合成 RAM 中复核运行原曝光换算函数，查到启动后的 SVR 更新；具体见 [SENSOR_EXPOSURE_TIMING.md](SENSOR_EXPOSURE_TIMING.md)。另已分离并完整解析官方 FPGA 配置报文，见 [FPGA_BITSTREAM_RESEARCH.md](FPGA_BITSTREAM_RESEARCH.md)。两项均为离线研究，尚未建立物理积分边沿与可用事件之间的对应关系。

## 输入与验证范围

固定输入为官方第一代 X1D 1.25.0 中 wedge 对应 bootimage pair 的解交织 FARM 应用：1808280 字节，装载基址 `0x100000`，SHA-256：

`317841f6f4dff599cda8c83f2b4912f78534db20e7690d0b14b0cd5f1b8c39ca`

本轮重新计算哈希并逐段核对指令。下文“已核对”均指该文件中的静态证据；不把官方文件地址、寄存器名称、软件调用顺序写成当前机身的实测感光时刻。

本轮没有相机请求，没有读写硬件寄存器，没有修改 FARM、FPGA 配置、原厂服务或无线程序，没有试闪、拍摄或读取照片。

## 真正的传感器接口

来源字符串 `0x2543e0` 为 `../src/fpga/sensorif.c`。

| 对象 | 静态位置 | 已核对的含义与边界 |
|---|---|---|
| 传感器接口启动 | `0x213fcc` 的命令零分支 | 应用配置后先向 `0x42000010` 写零，再写模式相关控制值；最终写调用在 `0x21410c`，返回到 `0x214110`。这是控制提交位置，尚不能称为实际感光起始边沿 |
| 模式控制值 | `0x2140a0–0x21410c` | 参数模式零写 `3`，模式一写 `7`，模式二写 `0x302`。这些是静态编码，本轮没有写入它们，也没有把所有模式套到普通拍照 |
| 像素数量 | `0x214520` | 读 `0x42008010` 后乘二；原厂诊断在 `0x214650` 使用该返回值输出 `status_pixels` |
| 起止同步标记 | `0x2145b8–0x2145ec` | 分别读 `0x42008000`、`0x42008004`；诊断输出将其对应到 `start / end -sync`。这是计数读值，没有硬件时间戳，也未证明对应完整感光窗口 |
| SAV / EAV 相关计数 | `0x214580–0x2145b4` | 读 `0x42008008`、`0x4200800c`，对应诊断中的 `blank- sav / eav`；不能仅按字符串把它们当作曝光开始和结束 |
| 调试状态与溢出计数 | `0x214634`、`0x214564` | 分别读 `0x42008018`、`0x4200801c`；诊断标签为 `status_debug`、`if-overruns` |
| 另一个进度读数 | `0x2144c4` | 在 PL 状态检查成功后读 `0x42008020`；调用者包括放大预览中等待行进度的逻辑。尚不命名为曝光时间戳或帧序号 |

诊断输出的参数位置可从 `0x214660–0x214688` 与 `0x2146f0–0x214728` 独立复核。诊断函数随后比较起止标记计数是否相同，用来识别数据流异常；这进一步说明计数与数据接收有关，但不等于曝光物理边界已经确定。

### 原第三候选仍含轮询等待

电子快门流程中，`0x1c4378` 调用 SENSORIF 启动，随后在 `0x1c4454` 读取上述像素数量，`0x1c445c` 与 99 比较。没有达到阈值时，先检查超时，再在 `0x1c444c–0x1c4450` 以参数 25 调用原任务延时函数，之后重读。

因此 `0x1c4464` 是“任务观察到计数已超过阈值”的位置，**不是像素第一次到达时的硬件中断**。本轮不把 25 个节拍声称为实测 25 毫秒，也不把计数阈值当作全幅像素开始或结束感光。计数如何复位、怎样确定属于本次采集，仍未完全还原。

## FARM 中断路径

IRQ 向量 `0x100770` 保存通用寄存器、浮点寄存器和状态后，经 `0x1007c8` 调用 `0x18b034`。后者根据中断编号查找函数和回调参数并调用处理器；返回路径完成中断结束处理。

`0x109508` 的实现与 `XScuGic_Connect` 的注册语义吻合：检查实例、编号和处理函数后，把处理函数与参数写入表。平台包装 `0x2273a0` 在 `0x227400` 调用它，并登记 PL 中断。此命名由指令与 Xilinx 接口语义对照得到，不是从未剥离符号表直接取得。

已找到平台包装的 13 个直接调用点；下表按用途合并。这里不把直接调用扫描等同于对所有间接调用的形式化证明。

| 中断 | 注册调用 / 处理器 | 本轮核对的用途或处理行为 |
|---|---|---|
| 63 | `0x1f9dc4` / `0x1f64ac` | `ddr3.c` 通道事件。检查 `0x4a000008` 中相应通道位，清除后唤醒通道等待对象 |
| 64 | `0x2155b8` / `0x214e04` | **USB**。来源为 `../src/fpga/usb.c`；处理 `0x48000038` 的 pending 位并通知 USB 任务，不能因代码邻近 SENSORIF 就当作传感器中断 |
| 65 | `0x205da4` / `0x2058f4` | 原始校准统计相关路径，涉及 `0x44140068` 及多项统计读数，并更新 `0x4413xxxx` 校准寄存器；周边配置来源为 `rawcalibmaps.c`。未证明是曝光起始事件 |
| 67、68 | `0x21235c`、`0x212384` / `0x2122ac` | `s2mm.c`。按配置调用回调或唤醒等待对象；两个实例的寄存器基址为 `0x41000000`、`0x4c000000`。数据搬运事件不能直接当作感光开始 |
| 84、85 | `0x1fdb50`、`0x1fdb78` / `0x1fdad8` | `mm2s.c`。唤醒实例等待对象；两个实例对应 `0x46000000`、`0x4d000000` 寄存器组 |
| 88 | `0x1d3fa4` / `0x1d3f48` | `preflash_service.c`。把已启动的预闪服务状态从等待改成中断已到；不是已证明适用于每次普通曝光的起点 |
| 89 | `0x1a46c4` / `0x1986d8` | 调用对焦数据读取并将事件写入对焦处理队列，不能当作任意拍照的曝光中断 |
| 52 | `0x22097c` / `0x1079bc` | PS GPIO 分发。上层回调 `0x220494` 处理通信输入和 GPIO 46；后者进入 `cfv_esc.c` 的 FSYNC 状态机，未证明 X1D 普通拍照使用该外部后背同步链路 |
| 从参数取编号 | `0x183944` / `0x180e58` | 来源 `../system/sata/sata_driver.c` |
| 从参数取编号 | `0x236fb4` / `0x237a74`；`0x237ffc` / `0x238550` | 来源分别为 `uart16550.c`、`uartps.c` |

另外已识别的直接 GIC 注册用于系统定时器与 PS DMA。**到目前为止没有建立 SENSORIF 起止同步标记到某个已注册、可供本功能使用的曝光中断之间的对应关系。** 这不证明 FPGA 电路中绝无相关信号或尚未使用的中断线路。

## 两类容易混淆的同步点

- `0x1fbda0` 等待 `0x442c8004` 的 bit 0，超时文字为 `Timeout waiting for VSYNC`；同一函数的来源是 `../src/fpga/lightmeter.c`。只能确认这是测光模块的等待条件，不能以 VSYNC 名称直接认定为本次感光起点。
- `0x1f0a1c` 输出 `Start AF sync output`，随后修改 `0x442c000c`；同组代码配置对焦同步延迟。它属于自动对焦模块，不应在未建立模式与信号对应关系前借用来触发普通闪光。

## 主处理器直读的线索与缺口

官方 wedge DTB 的 WEIM 节点声明从主处理器物理地址 `0x08000000` 开始、长度 `0x08000000` 的总线窗口，子节点 `vhfpga@0,0` 为 `simple-bus`。节点没有给出 SENSORIF 寄存器转换规则或专用曝光中断。

FARM 的 `eim.c` 路径会配置数据搬运与传输。窗口存在不代表可以把 FARM 地址简单加减常数后从 Linux 读取。尤其不能在尚未辨明数据端口与寄存器端口时扫读总线，因为读取数据端口可能消费原厂数据。

后续已解开原厂 Linux 内核并恢复其符号表，确认存在内建 EIM 驱动：普通 `read` 固定拒绝，唯一 `ioctl` 用于 DMA 数据搬运，`poll` 查询该传输是否仍在进行。驱动映射 `0x08000000` 起的 4096 字节用于数据传输，没有提供上述 SENSORIF 状态的读取或曝光中断接口。内核测试图样用的 `counter` 也不是传感器计数。完整来源、地址和离线复核见 [LINUX_EIM_RESEARCH.md](LINUX_EIM_RESEARCH.md)。

因此当前还没有证实能从 Linux 以固定、无清除副作用的地址直接读取上述曝光相关状态。没有打开机身物理内存或 EIM 设备，没有试读或枚举寄存器；不能把现有 DMA 完成通知接成新的曝光起点。

官方 `suc2farm-setup.sh` 还说明 wedge 的 SUC 通知输入使用与其他板型不同的 GPIO，并用 LED trigger 把该输入关联到 FARM 侧输出。因此这条板级 GPIO 线有通信通知用途的直接配置证据，仍不能当作独立曝光信号。本轮只读脚本，没有执行其中的模块或 GPIO 配置。

## 当前实施障碍

1. 需要先证明一个属于本次拍摄的硬件条件，并区分电子与机械快门、预览、冲洗及预闪；不能只按中断编号或同步字符串选源。
2. 如必须在 FARM 内导出该事件，仍需解决临时执行区、指令缓存同步和可靠恢复。具体缺口见 [PHASE_EVENT_RESEARCH.md](PHASE_EVENT_RESEARCH.md)。本轮没有用原厂刷写脚本或修改中断表来试探。
3. 无线芯片位于主处理器的正常驱动链路上；即使取得 FARM 中断，事件跨处理器传送与无线提交仍需接通和测量。不能把“找到中断函数”写成“波形已同步发出”。

四条软件通知的两张既有样本保留在 [EVENT_OBSERVER.md](EVENT_OBSERVER.md)，仅作为历史测量记录；它们已不作为继续寻找同步源的方案。本轮没有通知到无线发射、无线到闪灯发光或物理曝光窗口的新增测量。
