**第一次试拍后的更正：** 最初只覆盖 `0x1c4318` 这一处普通拍摄通知调用。用户报告拍完后，四个入口代码仍匹配且启用位有效，但快照为零事件，普通拍摄对照也未命中；这次结果不能判断第七条是否执行。

随后已补充同一 `0x1c3810` 通知的另两个原厂调用点 `0x1c52a0`、`0x1ca0b4`，复用原来的普通拍摄包装。原 520 字节驻留代码保持不变，不覆盖旧代码，不要求重启。补充流程只允许已验证的初版四入口且记录完全为空的状态；初次空结果单独保存。扩展已实机完成，六个调用点回读通过，重新启用时记录仍为空，USB 已关闭。用户选择这轮插上单点热靴引闪器再拍。

扩展后的 ARM 模型仍为两个布局各 7 项测试，装载模型增为 11 项：六入口完整装入/恢复共 1,048 个故障位置，初版空窗口扩展另有 174 个故障位置，均通过。装载器到新窗口准备完成累计 5,361 次请求、411 次写入；加首轮 12 次只读请求为 5,373 次请求。此窗口的后续结果见本页顶部；用户将最后试拍明确为第三次，不自行推定中间每张照片与事件的对应关系。

| 原 FARM 调用点 | 保留的原目标 | 记录含义 |
|---|---|---|
| `0x1c4318` | `0x1c3810` | 普通拍摄流程对照标记，不能当作实际曝光起点 |
| `0x1c52a0`、`0x1ca0b4` | `0x1c3810` | 补齐同一通知的另外两处调用，记录相同对照标记 |
| `0x1ce150` | `0x1c818c` | 第七条已知消息分发入口，只记录载荷的模式字节 |
| `0x1c8874` | `0x23899c` | 已走到 bit 5 拉低之前的读取调用 |
| `0x1c8950` | `0x1c7fdc` | sensor 启动调用及其后的原厂条件等待已返回 |

第七条入口读取模式 0～4。静态控制流中，模式 0、1 还需满足 `0x21f67c` 返回 1，才走 FPGA 脉冲分支；模式 2、3、4 跳过该段。脉冲分支先检查/请求原厂同步使能，再经 `0x1c8894` 清除寄存器 `0x40000030` 的 bit 5，经 `0x1c88d0` 置位，随后 `0x1c8904` 调用 `0x213fcc`。这些原厂写入均保持原样。

记录点放在拉低前及 sensor 调用后的原厂等待之后。不会在脉冲两沿之间或脉冲结束到 sensor 调用之间插入记录。仍有少量额外指令开销；这是路径观察，不能当成无扰动的物理时序测量。用户提供的微秒级实测是用户观察，本记录器不重新测量该值。

## 记录与判读

每个原 `BL` 改为调用对应包装，包装保存 `r0–r12`、`lr` 和 APSR，再尾跳到原目标；原目标看到的返回地址仍为原调用点加 4。代码不访问 MMIO、不调用系统服务、不保存照片、序列号或消息其他内容。

记录布局为 `G7R1`，96 字节，最多 16 个按到达顺序保存的事件，不覆盖旧事件，不读取计时器。只记录阶段与入口模式。一次有限的独占写尝试失败时记录丢失标志，不等待；满载标记溢出。主机通过前后序号、锁状态和编码校验接受快照。

- 有入口事件：证明命中了已知第七条入口；不能由此推断已经产生闪光。
- 有脉冲分支事件：证明到达原厂拉低前的调用；不能当成实际热靴输出或灯已发光。
- 有 sensor 后续事件：证明到达原调用后的代码位置；不能用它定位感光窗口。
- 有普通拍摄标记而无第七条事件：在安装、启用、记录完整性和观察窗口均核实的条件下，只能报告本次未记录到这些第七条检查点。
- 零事件、丢失、溢出、记录被重启清除或代码不匹配，都不能解释为“没有走第七条”。

## 装入与恢复约束

520 字节候选位于原厂空白 RAM `0x2b2880`，记录位于 `0x2b2a28`；与 R5 对焦主体不能共存。固定预检核对原 FARM 来源、主机协议实现、四个调用点、已知对焦入口、R5 八段覆盖区、完整空白区及 SGI/cache 状态。本轮 4500 速度值仅作为要保持的现状，不将它命名为固件固定默认值，也不写速度。

先完成原有 RAM/cache 探针并恢复暂存槽，再上传完整候选、维护缓存、逐个校验和替换四条指令。完整回读成功后才允许启用一次记录窗口。没有自动拍摄、对焦、试闪、重启或永久刷写入口。

任何传输结果不确定即停止，不自动重试写入。每次写入前保存恢复记录。解除时先停止记录、核对生产者空闲，再恢复四条原指令和缓存；保留不再引用的候选内存直到用户手动重启，避免回收仍可能被任务持有的返回位置。
