# 提前创建菜单：部署记录

目标：主菜单和引闪主页优先，争取约两秒可用；分组、引闪设置可随后后台准备。已认可的原生按键切换保持不变。对象创建、进程启动、窗口可见和实际首帧必须分开计时。

## 改动前这一轮冷启动的实测

- 原厂 GUI 进程启动约 0.60s，独立加载器启动约 2.77s；独立页面启动约 8.85s；原生按键控制约 10.77s 就绪。这里原厂的 0.60s 不是原厂界面已可交互的证据。
- 开机自动加载成功，用户确认按键延迟明显改善，并认可当前速度。
- 初次进入参数页的原厂服务请求耗时约 197ms；参数页与自定义菜单之间的请求及显隐确认约 5–11ms。不能把整个“取景到参数页”的状态变化也说成二十毫秒以内。
- 后续同一实例已累计 106 次切换。保存的最近日志 `../native-input-candidate/reboot-native-timing.txt` 中，28 个显隐确认样本为 0–7ms；其中一次前键处理 314ms，包含参数页转换。尚无屏幕首像素测量。

## 本轮候选改动

- 独立服务触发改到原厂 GUI 使用的 `post-fs` 启动阶段。原厂 init 文件和 camera-gui service 没有修改。
- 校验、确认原厂 GUI 身份后，优先创建隐藏页面；随后再等待原厂按键映射，核对并接入前键。
- 保留所有地址、映射、文件版本核验。必要依赖等待从整秒改成较短轮询，总等待上限仍有界。
- 新增 `boot-timing.log` 分段：加载器进入、文件校验、原厂身份确认、页面进程创建、页面挂起点、独立页面修改完成、隐藏窗口、前键映射、输入就绪。
- QML 内容和原生热路径二进制未变。现有 QML 中主菜单与 FlashPage 都直接创建；分组等子界面当前仍随 FlashPage 对象树创建，没有本轮新增的延迟加载器。用户允许子页晚一点，不代表它们已经被改成分批预加载。
