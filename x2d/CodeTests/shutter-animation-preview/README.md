## 目的与范围

拍摄黑屏期间的界面反馈：纯黑背景，用户确认的 `Ciallo～(∠・ω< )⌒☆` 保持原样单行显示在底层。八片深灰叶片在中间层旋转合拢并遮住文字；将要闭合时，白色 ☆ 从中央缝隙跃到前景，沿抛物线运动。叶片和分界线铺满屏幕，没有圆形外围裁切或风景背景。本轮已按用户授权接入第一代 X2D 100C 4.2.0 的原厂界面状态。

适用目标为第一代 X2D 100C；浏览器预览不依赖任何固件，未构成对 4.2.0 或其他固件的实机兼容验证。叶片由 SVG 几何图形绘制，无照片或外部素材；这只是合拢效果示意，不是镜间快门机械结构仿真。

## 文件与依赖

- `index.html`：独立预览，包含 SVG、样式和时间轴代码。
- 依赖：支持 SVG、requestAnimationFrame 的现代浏览器；没有第三方包或网络资源。
- 双击文件即可打开；点击播放，可拖动时间轴或选择四分之一慢动作。

## 副作用与恢复

`index.html` 仅浏览器绘制，不访问相机、不自动发起网络请求、不修改拍摄时序，不安装任何设备文件。关闭浏览器即可结束。机内安装与恢复另见下文。`outputs/` 内的离线 GIF、分镜图、构建结果与声音素材只留本地，不默认交付；旧 GIF 代表当时版本，不是当前版本截图。

## 审阅步骤

1. 初始状态为纯黑底白字，完整颜文字包括行尾星星，均为单行排版。
2. 播放：深灰叶片向中心合拢并遮住文字，仅剩小缝时白色星星跃出；全闭合时文字被叶片遮住。
3. 结束：叶片展开到四角，整行文字保留，跳出的星星消退；再次播放可重复。
4. 拖动时间轴检查各阶段，改变总时长和播放速度比较观感。

## 状态与限制

当前默认总长 **400 ms**：合拢 100 ms、闭合停留 100 ms、展开 100 ms、叶片保持打开而星星继续飞行 100 ms。初始开口半径为 250（800×600 设计空间），叶片第一帧已在画面内，取消屏幕外起步与缓入。约 85 ms 时星星跃出；展开在 300 ms 完成，为取景恢复留出余量。此前 660 ms 候选已被取代。

最新展开终点覆盖屏幕对角线范围：八边形开口半径为 `400 + 300*tan(π/8)`，约 524.264，使斜边到达四角。起始与结束开口尺寸不同，展开不再停在最初的小开口。底层文字取消尾段淡出，最后 100 ms 仍可见；星星继续飞行，结束时底层完整颜文字恢复。此修正已写入持久 QML，前一版留为 `.before-opening` 备份。

机内 QML 已实现并在当前实例加载。原厂退出 exposing 会立即收起遮罩，另有两秒看门狗；动画时间轴不控制曝光、取景或拍摄时序。用户反馈旧动画可见约 400 ms，不作为精确实测；屏幕光学黑屏时长仍未测量。

依赖：Windows PowerShell、现有 WinUSB 接口及原厂 shell 通道；分析器只需 Python 标准库。白名单事件只包含相对启动时间、事件类型和值，不保存原始设备日志、照片路径或设备序列号。结果存放本实验 `outputs/blackout-probe/`，不默认提交。再次 Arm 会覆盖上次测量起点；使用 `-OutputDirectory` 可指定其他本地批次目录。

所有输出均是**软件间隔**：`gui_exposing_to_liveview` 是原厂 GUI 从曝光页面返回取景的状态间隔，`hide_to_show_request` 是包含曝光开始和完成事件的隐藏/显示请求间隔，`exposure_finished_to_liveview` 是曝光完成通知至界面返回取景。菜单、自动回放会中断第一种配对；没有曝光事件的隐藏/显示区间被排除，避免误算菜单停留时间。缺起点、缺终点、乱序不会补造结果。单次读取只保留最后 24 条匹配事件，达到上限会标记可能截断；未达到上限也不代表底层日志没有轮转丢失。Watch 在主机循环读取、去重合并，失败停止，不重试不确定 USB 请求；最长 60 秒，观察到曝光完成后另留五秒收集恢复事件。连续读取仍不保证完整覆盖。设备重启、进程更换或日志丢失时应重新 Arm。时间戳显示毫秒不代表毫秒级测量精度。

**这不是屏幕光学黑屏测量。** 日志不能证明像素何时变黑或首帧何时实际显示；确认真实黑屏须用外部高速录像或光电传感器与显示事件对照。本轮已完成七项离线分析测试及 PowerShell 语法检查；实机只读确认 GUI 哈希与固件基线一致，已取得下述软件事件样本。此前冻结画面的全线程跟踪入口不用于本探针。

## 声音素材与设置检查

来源为 [UwUpad 的 Ciallo 6](https://uwupad.me/sound/83899)。当前转换为约 0.533 秒、48 kHz、16 位双声道 WAV，使用原素材 100% 振幅；旧版为 44.1 kHz、35% 振幅。音频、解码依赖与编译产物只保留在 outputs，不随仓库分发；未确认素材再分发许可。

从仓库根目录执行 `python -B x2d/CodeTests/shutter-animation-preview/prepare_audio.py <本地素材路径>` 可离线生成构建所需 WAV；素材须自行取得，源码库不包含它。转换采用线性插值并保留原振幅，报告的是整数样本峰值，不是重建真峰值。

**实机只读检查：** `system_sound_level` 为 `E_SoundLevel_High(3)`，`sound_settings` 为 `E_SoundSettings_AfResult(1)`，`selftimer_sound_level` 为 `E_SoundLevel_Low(1)`。这证明当时原厂系统音量不是关闭，不证明自定义 PCM 输出已能被扬声器听见。没有写这些属性，也没有改混音器。

历史直接 PCM 候选依据厂商 tinyalsa 布局构建，但独占设备并影响原厂提示音，已被下述原厂客户端链路替换。不能使用旧库恢复默认开机播放。

## 关闭与恢复

仅关闭声音：创建机内 `/blackbox/x2d-shutter-audio.disable` 会使下次启动脚本退出；当前进程须单独停止。删除该文件可允许下次启动。运行期间按 `/tmp/x2d-shutter-audio.pid` 记录核对进程身份后停止，不能对所有 sleep 进程批量操作。相机重启后可由 `stop x2d-shutter-audio` 停止已被 init 管理的服务。

完整撤回新增效果的 `restore-persistent.sh` 必须用当前源文件和构建结果重新生成并审阅：旧包哈希不适用于下述原厂链路更新。执行前停止声音服务，脚本核对当前文件哈希，恢复原 bootstrap 并移除新增的动画、音频和启动配置，最后恢复系统只读；随后受控重载 GUI。它保留原菜单扩展。原 bootstrap 备份为 `/system/etc/X2dNativeMenuBootstrap.qml.before-shutter`；动画的前两版分别保存在 `.before-400` 与 `.before-persistent`。备份不放在 init 目录，避免被解析成启动配置。

恢复脚本已生成、暂存并通过 shell 语法检查，未在本轮实际执行。初次安装的旧恢复脚本只认旧动画哈希，不得混用。生成包、事务脚本和精确哈希见本地 `outputs/device-package/`，不默认交付。

本轮离线 QML 检查通过；没有自动触发拍摄或重启整机。本轮代码尚未提交或推送。

随后实机日志已记录多次 `AUDIO_PLAY_BEGIN` 与 `AUDIO_PLAY_FINISHED`，且 USB 调试自动停止后，独立声音进程仍存在。这验证软件播放路径完成并持续运行，仍不能代替用户对扬声器可听输出的确认。

### 原厂音频链路替换（上述排查之后）

- **用户反馈：** 跳过旧自定义库并冷启动后，原厂对焦成功提示音恢复。通过原厂 `test_audio_client` 的 WAV 播放入口，用户确认已听到自定义素材；该次是 35% 振幅版本。
- **静态分析：** 第一代 4.2.0 的 `audio.json` 将扬声器路由到同一 PCM 设备，支持采样率列表不含 44100；原厂播放经 `libaudioclient`、音频服务及其 I/O、混音器、APU 生命周期。旧库以 44100 直接打开 PCM 并在空闲期间一直持有，绕过了这条链路。冷启动对照支持“旧初始化造成干扰”，但尚不能把持续失声精确归因于某一采样率、时钟或功放状态。Headphone 控件为零也是原厂正常配置，不能据此判定静音。
- **离线验证：** 新库仅依赖固件 `libc` 和 `libaudioclient`；与固件测试客户端核对 44 字节流配置、16 字节流句柄、72 字节帧描述及关闭顺序。构建检查导入、AArch64 架构和段权限通过，不再导入任何直接 PCM 函数。
- **素材实测：** 持久素材为 48000 Hz、16 位双声道、25600 帧。样本峰值 23602/32768，即 72.028%、−2.850 dBFS，达到整数上下限的样本为零。100% 表示不再衰减，没有做峰值归一化；这不是扬声器声压或重建真峰值测量。
- **实现与部署：** `prepare_factory_audio.py` 离线生成精确旧哈希保护的更新事务，只替换旧音频库与 WAV，备份为 `.before-factory-audio`，失败恢复文件并禁用已知有问题的旧音频自启动。已授权执行的事务完成、哈希吻合、系统恢复只读；启动配置仍默认启用，动画文件保持原样。无自动拍摄、整机重启、提交或推送。
