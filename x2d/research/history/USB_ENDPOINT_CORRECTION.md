## 错误及直接纠正依据

错误来自本客户端的端点选择：将一个通用数据发送入口 `0x1805ba8c0` 当成 Phocus 控制回调真正使用的虚表入口，进而错误选取第一对 IN/OUT。首轮请求内容本身为固定版本读取，但被提交到了数据 OUT。这不是相机返回了拒绝或参数协议验证失败。

| 直接证据 | 对应关系 |
|---|---|
| `0x1805c8fb0` | Phocus 发送回调调用虚表 `+0x68`。 |
| USB 虚表 `0x180ebccb8 + 0x68` | 指向 `0x1805bab50`。 |
| `0x1805bab67` | 使用 `+0xc9`，是枚举时保存的第二个 OUT。 |
| `0x1805ba600` | 控制接收 mode0 使用 `+0xc8`，是第二个 IN。 |
| `msg2dbus 0x157bf2 / 0x157bfc` | 控制服务持有 `/ep2` 与 `/ep4`，线程名分别为 `USBCtrlOutEp2` 与 `USBCtrlInEp4`。 |
| `usb_bulk_raw_hbl 0x1960 / 0x198d / 0x19ba` | 三种 USB 速度的描述符顺序均为 OUT1、OUT2、IN1、IN2。 |

因此第二对才是这里的 Phocus 控制通道。更正实现要求四个 bulk 端点、方向顺序严格为 OUT/OUT/IN/IN，选择索引 1 的 OUT 与索引 3 的 IN；实际端点地址来自本次 Windows 描述符。它不会在多个候选间轮试。数据通道的 I/O 入口已移除。

## 数据 OUT 的消费者与首轮影响边界

官方生产启动项 `/etc/init/msg2dbus.rc` 启动 `msg2dbus`，USB 路径为 `/dev/usb-ffs/bulk`。`HostTransferServiceUsb::init 0x6aa20` 只建立 `UsbDataIn`，构造路径后缀 `ep3`（`0x157e6e`），在 `0x6ab38` 构造发送对象并启动 `USBDataInEp3` 线程。

同服务的 `HostTransferServiceUsb::receive 0x6cd78` 没有打开/读取数据 OUT，而是通过 transfer 的虚方法返回错误，文字为 `Not implemented`（`0x157e96`，15 个 UTF-16 字符）。因此在已定位的正常 Hasselblad 主机传输服务中，没有实现数据 OUT 的常规接收处理链。描述符辅助程序 `usb_bulk_raw_hbl::main 0xfa8` 打开 ep0、写入描述符/字符串并保持进程，不是 ep1 数据接收器。

正常控制接收则由 `MessageIO_USB::init` 检查端点文件存在并启动 ep2/ep4 线程；`USBCtrlOut::process 0x47348` 打开 ep2，`0x47570` 读取并交给控制消息解析。首轮选中的 ep1 没有走这条 ReadParameter 分发链。

这支持“误选到没有上述常规接收流程的数据 OUT”作为发送超时的解释。**仍不能由这些静态代码或主机 121 错误证明首轮字节实际未到达、已被丢弃或被某个消费者处理。** 固件还包含通用 DJI USB 传输库；尚未建立它在本机生产启动中消费此端点的调用链，也未核对实机运行态。没有为此追加请求、读取相机日志、执行清理/复位或照片操作。
