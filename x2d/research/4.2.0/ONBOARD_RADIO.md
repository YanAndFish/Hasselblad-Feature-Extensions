# X2D 4.2.0：机内无线普通引闪

记录：2026-09-12。目标是用第一代 X2D 自身无线芯片发送 Godox 普通引闪波形，并与曝光同步。以下均为官方 4.2.0 静态证据，未装载固件、写 PHY、发射或测量；输入哈希见 [sources.json](sources.json)。

## 固定平台

固件包含 `bcmdhd.ko`、BCM43752A2 日常及 mfg 镜像。`start_wifi_factory.sh` 静态指定 `fw_bcm43752a2_ag_mfg.bin`；执行该脚本会改变无线状态，本研究没有执行。

日常镜像内部标记为 `4362a2-roml/config_sdio_release_dji`，版本 `18.35.387.23.16801.1`；mfg 为 `4362a2-roml/config_sdio_mfgtest_he`，版本 `18.35.387.23.15`。文件名与内部 4362 系列标记应一并记录，不能误当两个不同硬件结论。

驱动 `dhdsdio_probe_attach` 的 43751/43752 分支设置 RAM 基址 `0x170000`，与镜像代码、指针交叉一致。这不是实机芯片 ID 测量。

## 已定位的入口

通用 `wl` 工具确有 `phy_macfifo_play` 处理器（ELF VA `0x480f30`）：查询版本、容量，检查非零且四字节对齐的样本长度，分块通过 `phy_macfifo_play_data` 上传，再调用播放控制。但是当前两份无线镜像没有对应名称，尚未证明固件端支持；不能把 CLI 存在当作可用性证明。

mfg 镜像有 `phy_tx_tone` 及 `phytable` 的真实 iovar 注册和分发。下列地址采用上述 RAM 基址：

| 路径 | 静态调用与限制 |
|---|---|
| tone | `0x19dac0` → `0x19da8a` → 回调 `0x1976a4` → `0x197580` |
| 继续进入 ROM | `0x197580` 调用 `0x5ffc0`、`0x60268`；停止分支涉及 `0x60494` |
| phytable 写 | `0x197e64` → `0x197a38` → `0x197a08` → ROM `0x6e650` |
| phytable 读 | `0x197e64` → `0x197b00` → `0x197ad0` → ROM `0x6e378` |

`phytable` 的读写包装均涉及 PHY 控制调用与恢复，不是单纯内存复制。普通 tone 使用固定非零参数进入缺失的 ROM 路径，尚不能证明“先写入任意样本，再启动 tone”会保留并原样播放该样本。`sample_collect` / `sample_data` 也不能直接命名为播放接口。

mfg TCAM 表为 `0x22d9b0..0x22e070`，216 项；日常版为 `0x21e7e4..0x21f0bc`，283 项。已核对这些表均没有覆盖上述 ROM 入口字节。日常版 RAM tone 函数 `0x1926a4` 也调用相同的 `0x5ffc0` / `0x60268`。这说明只检查 mfg 表并非当前缺口的唯一原因；仍不能排除函数内部其他补丁或机制。

尚无匹配型号与版本的 ROM 字节或可靠符号，故不把 `0x5ffc0`、`0x60268` 武断命名为样本生成器、单次播放函数，也不把参数 `0xffff` 当作已证循环次数。

## 曝光关联及未完成项

`librcam.so` 的 `Camx_StartExpo` 在两个互斥分支调用 `FsyncCtrl_TriggerXsync`，地址与前序证据见 [电子快门分支](../history/ESHUTTER_BRANCH_ANALYSIS.md)。热靴分支中的 1000 微秒等待不能直接解释为射频提前量；函数调用顺序也不能当作物理曝光时序。

尚缺匹配 ROM、样本存储位置及格式、定长播放和完成语义、正常可用的装载入口、曝光事件到 RF 发射的时延与抖动测量。没有可安装的 X2D Godox 补丁或已验证的完整发送链。

X1D 的用户成功案例仅是不同平台参考，不迁移其地址或镜像。后续若获授权设计额外无线提前量，必须独立叠加并保留原厂动态 Fsync 修正，零值保持原厂行为。
